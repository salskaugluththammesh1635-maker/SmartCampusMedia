# d810 加固版上板测试方案（2026-10-31）

> 适用位流：`reports/d810_fix_20261031/smartcampus_media_d810fix_20261031.bit`
> （629,640 B，2026-10-31 17:24，setup +1.935 ns / hold +0.011 ns，0 违例端点）
>
> 本文回答「这一版位流该怎么完整测」。它是
> [board_verification_2026-10-27.md](board_verification_2026-10-27.md) 的**增补与修正版**：
> 旧方案针对的是 10-27 的位流，此后系统新增了自适应缩放、淡入淡出转场、
> OSD 字幕、`dd`/`dE` 两个错误码，**其中一条旧判据已经失效**（见 §6.2）。
>
> **本版位流的验证档位仍是「仿真 + 综合布线」**，本文描述的是把最后一步补上的操作。

---

## 零、这版位流要验什么

一句话：**先判 `d810` 死没死，再回归新功能，最后跑边界。**

本版相对 10-30 版的全部差异只有五处（详见
[d810_fix_2026-10-31.md](d810_fix_2026-10-31.md)）：

| # | 改动 | 上板可见表现 |
|---|---|---|
| 1 | `loader_enable`/`store_enable` 改为寄存器输出 | 消除可能把 loader 意外复位的毛刺 |
| 2 | `image_player` 接出 loader `busy`，16 拍无响应报 **`dd`** | 正常时无影响；异常时不再拖 4 s 才报 |
| 3 | 装载中失去 SD 授权 → 退回 `C_WAIT` 保留 `pending` | 正常时无影响；异常时自动重装而非报错 |
| 4 | `T_FATLOC` 加 `2×BLK_TIMEOUT` 看门狗 → **`dE`** | 正常时无影响 |
| 5 | 顶层仲裁改显式独热；`fat32_reader` 握手超时改报码 7 → **`dA`** | 正常时无影响 |

> **关键含义**：这五处在**正常路径上不改变任何行为**，仿真里 CASE 1~12 全部照旧通过。
> 所以测出来的任何功能回归都更可能是「本来就有的问题」，而不是本次加固引入的。

## 一、准备（10 分钟）

### 1.1 素材

| 目录 | 内容 | 用来验什么 |
|---|---|---|
| `good\` | `IMG001`~`IMG006.BMP`，640×480 24bit，921,654 B | 正常播放全链路 |
| `bad_bmp\` | `IMG001` 正常 + `IMG002` 签名是 `XX` | BMP 头校验 → **`b1`** |
| `bad_size\` | `IMG001` 正常 + `IMG002` 是 320×240 | **缩放通路 → 居中显示（不再报错，见 §6.2）** |
| `empty\` | 只有 `README.txt` | 卡好但零张图 → **`00`** |

素材生成脚本行为见 [board_verification_2026-10-27.md 附录 B](board_verification_2026-10-27.md)。

### 1.2 硬件

- HDMI 线 + **支持 640×480@60Hz** 的显示器（老旧显示器可能不认这个模式）
- SDHC 卡（≤32 GB），**FAT32 主分区**
- 3.5 mm 有源音箱/耳机（验第二条音频通路）

### 1.3 全程记录什么

数码管 4 位（左→右）+ LED[7:0] + 屏幕现象，**每个用例都记**。
数码管格式：`[错误类别|播放状态] [子码|内部错误码] [图号低4位] [测试图案序号]`
正常运行时是 **`3 0 1 0`**（就绪 / 无错 / IMG001 / 彩条）。

## 二、阶段 A：`d810` 判决（5 分钟，**先做这个**）

这是本版位流唯一的目的。**做完这一阶段再决定要不要继续测其余部分**——
如果这里就报错，后面的功能测试没有意义。

### A.1 操作

插好 `good\` 卡 → 烧录位流 → 上电（或按复位）→ **手离开键盘，看 5 秒**。

### A.2 期望时序

| 时间点 | 数码管 dig3 | LED | 含义 |
|---|---|---|---|
| 0~5 ms | 0 | 只有 LED[5] | 上电复位（`POWERUP_CYCLES = 131_071`） |
| 5~8 ms | 0 | 只有 LED[5] | 探针延迟（`PROBE_DELAY_CYCLES = 200_000`） |
| 8 ms~0.5 s | 1（扫描） | LED[0] 灭 | CMD0/ACMD41 + 枚举 `IMGnnn.BMP` |
| 0.5~1.2 s | 2（装载） | **LED[6] 亮** | 读首图 1,801 扇区，12.5 MHz SPI 约 0.59 s |
| **1.2 s 后** | **3（就绪）** | **LED[0] 亮** | 首图就绪 |

**屏幕**：IMG001 的画面——深蓝底 + 40px 白框 + 中央黑色数字 `1` + 右下 1 个白方块。

### A.3 判决表

| 结果 | 结论 | 下一步 |
|---|---|---|
| **出图 + 数码管 `3 0 1 0` + LED[0] 亮** | 加固覆盖了现场成因 | A6 可改 ✅，继续阶段 B |
| **仍是 `d810`** | 还有第三条成因链，本次没打中 | 停，记录完整现象发回分析 |
| **变成 `dd`** | 现场确实存在「start 没被接收」，只是旧版抓不到 | **毛刺假设被实锤**，继续记录 |
| **`dE`** | FAT 定位段无进度 | 卡侧/SPI 问题，先换卡 |
| **`dA`** | 块握手超时，请求没人收 | 总线归属问题 |
| 停在 `2`、LED[6] 常亮不灭 | 装载卡住 | 记下持续多久、最终报什么码 |

> **注意**：`dd`/`dE` 是本次新增的码。**看到它们不是"更糟了"，而是"终于能定位了"**——
> 旧版这两个场景都只会拖 4 秒报一个 `d8`。

## 三、阶段 B：显示链路（10 分钟）

### B.1 八种测试图案（KEY4 / KEY5）

按 KEY5 逐个切换，dig0 应依次为 0~7：

| dig0 | 图案 | 期望 |
|---|---|---|
| 0 | 八色彩条 | 白 黄 青 绿 品红 红 蓝 黑，从左到右八条（每带 80px） |
| 1 | 64px 网格 | 10 条竖线 + 8 条横线，黑底白线，等间距 |
| 2 | R 渐变 | 只有红从左到右渐亮（约 31% 封顶），绿蓝全 0 |
| 3 | G 渐变 | 同上 |
| 4 | B 渐变 | 同上 |
| 5 | 纯色 | 纯黑 |
| 6 | 移动方块 | 极深蓝底（RGB 0,0,32）上 64×64 绿方块，约 1 秒移动 64px，往复 |
| 7 | 棋盘格 | 16×16 像素一格，40 列 × 30 行，白黑相间，边缘锐利无灰边 |

> 颜色顺序错乱 = TMDS 三通道映射反了；某色偏色 = 该通道位序错。

### B.2 亮度五档（KEY7）

连按 KEY7，亮度依次 100% → 87.5% → 75% → 62.5% → 50% → 回 100%。
**黑色区域必须始终纯黑**（不能因为提亮而发灰）。

### B.3 反色（KEY8）

按一下全画面反色，再按恢复。判据：**OSD 字幕与信息条不受反色影响**（它们走独立叠加层）。

### B.4 三个叠加层（KEY11 / KEY12 / KEY13）

| 键 | 功能 | 期望 |
|---|---|---|
| KEY11 | 九宫格参考线 | 2×2 分割线 + 中心块叠加在画面上 |
| KEY12 | 底部信息条 | 显示图号 / 模式 / 轮播状态 / 亮度档 |
| KEY13 | 音频图层 4 态 | 关 → 电平条 → 波形 → 电平+波形 → 关 |

## 四、阶段 C：图库与装载（15 分钟）

### C.1 图库切换 + 转场（KEY0 / KEY1）

按 KEY1 六次，跑完 `IMG001`~`IMG006`：

| 按 KEY1 | dig1 | 屏幕 |
|---|---|---|
| 0 | 1 | 深蓝底 + 数字 1 + 1 个方块 |
| 1 | 2 | 深绿底 + 数字 2 + 2 个方块 |
| 2 | 3 | 深红底 + 数字 3 + 3 个方块 |
| 3 | 4 | 深黄底 + 数字 4 + 4 个方块 |
| 4 | 5 | 深青底 + 数字 5 + 5 个方块 |
| 5 | 6 | 深紫底 + 数字 6 + 6 个方块 |
| 6 | **1**（回绕） | 回到深蓝底 |

**判据四者必须一致**：图号、背景色、中央数字、方块数量。
KEY0 从第 1 张按一次应**回绕到最后一张**（第 6 张），这是设计行为。

**转场本版行为**：`FADE_EN=1`、`FADE_FRAMES=8` → 淡出到黑 8 帧 → 换帧 → 淡入 8 帧，
往返约 **286 ms**（8×2×16.7 ms）。**不应出现硬切**，也不应卡在中间灰帧。

### C.2 快速连按（关键回归项）

**连按 KEY1 十次以上，全程盯屏幕**：任何一拍闪白即判失败。

> 这是 2026-10-29 修复的「切图白条」复验点：`video_content_mux` 在 `image_ready`
> 落下时曾回落纯白彩条，现在有图期间读欠载补黑（`image_ever_ready`）。
> 本版位流包含该修复，但**上板从未确认过**——10-31 那次图片根本没出来，无从判定。

### C.3 自动轮播（KEY2 / KEY9）

1. KEY2 → **LED[1] 亮**（auto_play）
2. 等 5 秒 → 自动跳下一张，dig1 加 1
3. KEY9 改档：×2 = 10 s、×3 = 15 s、×4 = 20 s，**改档立刻重新计时**（不接着算）
4. 再按 KEY2 → LED[1] 熄灭，停止轮播

### C.4 图库重扫（KEY10）

保持上电，**拔卡换成加了 `IMG007.BMP` 的卡**，插回，按 KEY10：
dig3 应短暂回 1（扫描）→ 回 3（就绪），dig1 能数到 7。

> `sd_probe` 是上电单次执行、成功失败都锁定，**KEY10 只重扫图库，不重新初始化 SD 卡**。
> 这是设计取舍（`rtl/storage/sd_probe.v`），不是 bug。

### C.5 自适应缩放（**本版新增能力，必须验**）

用 `bad_size\` 卡（`IMG002` 是 320×240）：

| 期望 | 说明 |
|---|---|
| 按 KEY1 切到 IMG002 → **屏幕中央出现 320×240 的小图，四周黑边** | `bmp_parser` 是 `CHECK_SIZE(0)` 放宽模式，`img_scaler` 做 1:1 居中 |
| 数码管 **不报错**，dig1 = 2 | 不再走 `b2` |
| 小图清晰不发糊 | 只缩不放，1:1 不像素复制 |

**再验一个缩小场景**：放一张 1280×960 的图 → 应缩放到 640×480 全屏显示（保持宽高比）。

## 五、阶段 D：模式与音频（10 分钟）

### D.1 模式循环（KEY3）

按 KEY3：日常 → 科普（青条页）→ 应急（全屏红底）→ 日常。
科普页是独立 640×480 RTL 页面（FPGA 与数字逻辑入门），**不依赖 SD 卡**。

### D.2 应急直达（KEY15）

任意状态下按 KEY15 → **立即**全屏红底告警（`LED[3]` 亮），再按退出。

**关键判据**：应急模式下**禁止切图与轮播**——此时按 KEY1 / KEY2 应无反应。
这是安全设计：应急响应不能依赖用户按对顺序。

### D.3 两路静音的独立性（交叉验证）

| 键 | 作用 | 不该影响 |
|---|---|---|
| KEY6 | 静音 **HDMI 内嵌 + 3.5 mm** 两路音频 | 蜂鸣器提示音 |
| KEY14 | 静音**蜂鸣器** | 两路音频 |

「按 KEY6 蜂鸣器还响」「按 KEY14 音频还在」才是**正确**的。

### D.4 音频

- **3.5 mm**：有音、底噪可接受
- **HDMI**：需电视/显示器支持；音量已被右移 6 位（1/64 ≈ −36.12 dB），**极低音量属正常**
- **蜂鸣器**：三档音调随状态变化

## 六、阶段 E：异常注入（15 分钟）

### 6.1 `bad_bmp\` → `b1`

**操作**：插 `bad_bmp\` 卡 → 断电重上电 → **按 KEY1 一次**。

| 观察点 | 期望 |
|---|---|
| 数码管 | **`b 1 2 0`** |
| LED[7] | 亮 |
| 蜂鸣器 | 静默 1.5 s 后响 3 s |
| 屏幕 | **仍显示 IMG001**（装载失败，前台保留旧帧） |

> **⚠️ 必须按 KEY1**：`bad_bmp\` 的 IMG001 是正常的，首图装载成功，此时不报警。
> 不按 KEY1 就判「测试失败」是误判。
>
> **为什么屏幕还是 IMG001**：失败发生在 `C_LOAD` 阶段，还没走到 `C_COMMIT`，
> 前台帧没被替换。这是双缓冲的正常行为。

### 6.2 `bad_size\` → **期望已变更（旧判据失效）**

> **这是本方案与 10-27 版最重要的差异。**
>
> 10-27 版写的是「`bad_size` → `b1`」。**现在这条不再成立**：
> `image_player.v:342` 实例化 `bmp_parser #(.CHECK_SIZE(0))`，尺寸校验已放宽，
> 320×240 的图不再被判为「宽高不符」，而是**正常缩放居中显示**。
>
> **如果按旧文档测，会看到"应该报错却没报错"，从而误判为测试失败。**
> 详见 [c2_scaler_2026-10-30.md](c2_scaler_2026-10-30.md)。

| 素材 | 现在的期望 |
|---|---|
| `bad_size\`（320×240） | **正常显示小图居中 + 黑边，不报错**（见 §C.5） |

仍然会报 `b1` 的只剩：签名非 `BM`、非 24bit、有压缩、数据偏移越界、宽高为 0。

### 6.3 `empty\` → `00`

直接上电（**无需按键**）：数码管 **`0 0 1 0`**、LED[7] 亮、1.5 s 后响 3 s、
屏幕只有测试图案（无图可放）。

> 这是最容易被漏测的盲区：改造前这种情况灯全灭、屏幕放测试图，看起来和正常启动一模一样。

### 6.4 拔卡重扫

上电运行中**直接拔卡** → 按 KEY10 → 应重新扫描并回到 `00` 状态；
不应死机、不应花屏。插回后按 KEY10 可恢复。

## 七、阶段 F：稳定性（30 分钟以上）

| 项 | 操作 | 判据 |
|---|---|---|
| F.1 长跑 | 连续播放 30 分钟 | 无花屏、无错码、LED[2] 全程不亮 |
| F.2 快速切换 | KEY0/KEY1 交替狂按 30 秒 | 无错码、不卡死、画面始终有效 |
| F.3 反复上电 | 断电重上电 5 次 | 每次都能在 1.2 s 内出图（这是 `d810` 是否偶发的关键统计） |
| F.4 KEY7~KEY14 逐键 | 每个键按一遍 | 对应功能响应，且**不互相串扰** |

> **F.3 特别重要**：`d810` 是偶发问题（10-29 正常、10-31 复现）。如果只上电一次就宣布
> 修好，证据强度不够。**建议至少 5 次上电，每次记录 A.2 的时序**。

## 八、判读速查

### 8.1 LED

| LED | 含义 |
|---|---|
| LED7 | 当前有面向用户的错误 |
| LED6 | 图片装载中 |
| LED5 | SDRAM PLL 锁定（**不亮则后面都不用测**） |
| LED4 | HDMI PLL 锁定且核视频锁定 |
| LED3 | 应急模式 |
| LED2 | 读 FIFO 异常（正常应**全程不亮**） |
| LED1 | 自动轮播开启 |
| LED0 | 图片就绪（`image_ready`） |

### 8.2 错误码（含本版新增）

| 显示 | 含义 |
|---|---|
| `C0` | 卡座报告无卡 |
| `C1`/`C2`/`C9` | CMD0 重试耗尽 / CMD8·CMD55 异常 / ACMD41·CMD58 异常 |
| `F1`~`F4` | MBR 签名错 / 分区表异常 / 不是 FAT32 / 找不到图 |
| `00` | 卡读通了但根目录没有 `IMGnnn.BMP` |
| `b1`/`b2`/`b9` | BMP 头非法 / 像素数与缩放配置不符 / 其他 BMP 错误 |
| `d1`~`d7` | SD 内部失败 / 读块失败 / 簇链异常 / FIFO 无空间 / SDRAM 仲裁或不在线 |
| `d8` | 装载无进度（4 s 兜底） |
| `dA` | 块握手超时（既无 `blk_done` 也无 `blk_err`） |
| `dB`/`dC` | SDRAM 初始化超时 / 写完成超时 |
| **`dd`** | **`img_loader` 未接收 start**（本版新增） |
| **`dE`** | **FAT 定位段无进度**（本版新增） |
| `d9` | 未归类的数据通路故障 |

## 十、失败时的排查顺序

先查底层，不要跳步：

```
1. LED[5] 不亮（SDRAM PLL 没锁）
   → PLL 参数问题，后续全部不用测

2. LED[4] 不亮但 LED[5] 亮
   → HDMI PLL 或发射核未对齐；先换线/换显示器确认 640×480@60 兼容

3. 数码管完全乱码
   → 段选/位选极性（本工程段选高有效、位选独热低）；某一位不亮 = COM 线虚焊

4. 报 d810 / dd
   → 装载链路问题。dd 表示 start 没进 loader，d8 表示 loader 没在跑
   → 带上完整读数（4 位全部）与上电时序，回代码侧分析

5. 报 dE / dA
   → SD 卡侧。先换卡，再查 SPI 分频（sd_spi_ctrl.v 的 SCK_FAST_DIV）

6. 报 C*/F*
   → 卡本身。重新格式化为 FAT32 主分区；确认 ≤32 GB

7. 画面花屏/斜纹
   → 时序参数或 SDRAM 侧。先看 LED[2] 是否亮（FIFO 溢出/下溢）
```
