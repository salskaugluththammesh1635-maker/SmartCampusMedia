# SD 卡上板 2110 排查（2026-10-20）

板上反馈 LED4、LED5、LED7 亮，其余灭，数码管显示 `2110`。在当前全链 bit 中，这代表两颗 PLL 锁定，图片链路的 FAT 定位阶段失败。

## 真实输入与复现

以只读方式读取 E 盘对应 SD 卡。根目录 `IMG001.BMP` 为 921654 字节，与仓库 IMG002.BMP（白底中央 200×200 红块）SHA256 一致。原始 FAT 目录短名也确实为 `IMG001  BMP`，文件首簇 6，完整簇链内容与源文件逐字节一致。

Windows 报告 `PartitionStyle=MBR`、分区偏移为 0。实际第 0 扇区包含 FAT32 VBR：512 字节扇区、每簇 8 扇区、保留区 32 扇区、2 份 FAT、每份 15336 扇区、根目录簇 2。四个分区表项全为 0。这是直接位于卡 LBA0 的 FAT32 卷，Windows 的 MBR 属性不足以证明卡上存在有效 MBR 分区表。

只读采集引导区、目录、文件簇链所需的 1805 个不同扇区，保存为 `reports/sd_card_2110/lba.hex` 与 `data.hex`。以下命令将扇区字节输入真实 `img_loader`、`fat32_reader`、`bmp_parser`，替换的只有 SD 块服务：

```powershell
powershell -ExecutionPolicy Bypass -File sim/scripts/run_sd_card_replay.ps1
```

修复前：只发起一次 LBA0 读取，`done=0 fail=1 err=1`，输出 `BOARD_DISPLAY=2110`；脚本返回 1。仅保留真实第 0 扇区的最小输入也复现相同错误，证明失败发生在目录和图片读取前。证据分别在 `reports/sd_card_2110/red_verified/` 和 `red_minimal/`。

## 原因与修复

旧 `fat32_reader` 固定把 LBA0 当作 MBR，从偏移 454 读取分区起始 LBA，见其为 0 就拒绝。这一失败经 `img_loader` 汇总为错误 1，最终显示 `2110`。

现在在读取 LBA0 时同时捕获 BPB 字段。只有 55AA 签名及相容的 FAT32 BPB 同时成立，才接受 LBA0 直接卷；卷起始地址设为 0。否则沿用原来的 MBR 第一分区路径。独立保存卷起始地址，避免将 VBR 启动代码中恰好位于分区表偏移处的字节当成分区地址。

没有改写 SD 卡分区、引导区、FAT 或图片。

## 验证结果

- 新增回归在修复前失败：LBA0 直接卷、直接卷正确数据区地址、VBR 启动代码不能充当分区地址。
- 修复后 FAT32 回归 40 条 PASS，原有 MBR 场景及新增非 512 字节扇区、FAT16 风格 BPB 拒绝场景均通过。
- 真卡原始输入回放通过：307200 个像素逐一核对，153600 次字写出，2028 次扇区读取，0 个缺失扇区，0 错误。结果见 `reports/sd_card_2110/green/`。
- SD 协议、SD 驱动、启动探针、BMP、img_loader、播放控制回归均通过；工程副本同步和静态检查通过。
- 32×16 异常场景及完整 640×480 图片全链回归重新通过。重新综合、布局、布线和 bitgen 完成，150MHz 同域建立余量 +0.102ns；SiP 0°/180°接口余量仍为 -3.537ns / -7.232ns，整体时序未通过。
- 发布审计已核对当前源文件及新 bit，证据无失配，状态为 `blocked_by_sdram_timing`。TD 重写工程时会输出 `Name="UsedInP&R"`，审计读取器在内存中转义这个属性名以便严格 XML 解析，原始工程字节保持不变。
