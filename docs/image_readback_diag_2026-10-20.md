# 7711 后的整帧连续读回诊断

## 已确认与尚未确认

分段 bit `image_path_diag.bit` 的用户反馈：数码管 7711，LED0/1/2 常亮，无红块。文件解码和 DM=0 的写命令中都出现过红色，但 SDRAM 有效返回与最终像素只出现白色。独立连续整帧 BIST 的 LED0/1 通过结果仍有效，两者覆盖的事务模式和布局不同。

本版本不改写入流程和图片内容，先把同一幅已装载图片直接连续读回 153600 字，逐字与白底中央 200×200 红块参考图比较，然后才放开原 HDMI 显示读出器。诊断扫描跳过显示仲裁器的读地址及请求调度；直接使用同一个真实 SDRAM 控制核。读回期间屏蔽仲裁器对这些非自身请求返回的计数，读完包含最后一项比较并留出 32 拍静默后再恢复显示。失败/超时也会结束诊断并通过 LED6 报告，`image_ready` 仍仅表示原控制流提交完成。

## 上板读数

用户已报告本版实测：**7711，LED0、1、2、6 常亮，无中央红块**。直接连续整帧扫描也只见白色且比对失败或超时，尚无红色进入正确物理地址的证据。写入命令数据出现红色不等于实际内存写入成功；下一步核对地址范围、稀疏逆序写组及实际接口。

保留原白底红块 SD 卡及 HDMI 接线，下载新的 **image_readback_diag.bit**，复位后等待 5 秒，报告数码管、常亮 LED 和是否出现红块。无需按键。

数码管仍为：解码 / 写命令 / 原始读返回 / 最终像素。原始读返回现在包含装载后的直接扫描和恢复后的原显示读出。每位 1=只见白色，5=见非白色但没有精确红色，7=见精确红色。

| 现象 | 含义 |
|---|---|
| 7777，LED6 灭 | 直接整帧比对通过，原显示像素也见到红色；还需实看红块位置 |
| 7771，LED6 灭 | 直接扫描确认内存内容正确，但原显示路径仍没读到红色；重点转向原读请求与地址 |
| 7711，LED6 亮 | 直接扫描也只读到白色；尚不能把写命令看到红色当作存入了正确内存位置 |
| 第三位 7，LED6 亮 | 内存读到过红色，但整帧数据或位置不符，或扫描超时 |

此版本 LED0～5 保持原分段含义，LED6/7 变更如下：

| LED | 含义 |
|---|---|
| 0 | 图片控制流提交完成，扫描已结束 |
| 1 | 解码见过红色 |
| 2 | 写命令见过红色 |
| 3 | 原始读返回见过红色，包含连续诊断扫描 |
| 4 | 原显示路径的有效 RGB565 见过红色 |
| 5 | 图片模式送入 HDMI 的 RGB888 见过红色 |
| 6 | 连续扫描的整帧比对不符或超时 |
| 7 | SD、装载或原像素 FIFO 异常 |

## 仿真范围与限制

分段测试覆盖正常图、解码/写数据/返回/像素四种纯白注入及白图重载；检查连续扫描结果和恢复后的完整显示帧。独立扫描器测试 12 项通过：未提交前不读、跨刷新正确、全白返回可识别、最后一个字出错仍报错、缺失返回有限超时。

同时建立真实 APUG011 加密核 + ISSI 管脚功能模型的对照脚本 `sim/scripts/run_eram_core_bus.ps1`：128 字的连续、稀疏正序、稀疏逆序、连续逆序及稀疏读五类功能用例均通过，未复现真实板纯白。使用已安装的 2022.1 Verilog 编译器 `-mfcu -permissive` 接受核中的无尺寸常量，不改加密 IP。旧 10.1d 编译器拒绝该常量，2022.1 SystemVerilog 模式又缺少标准包，失败日志保留在 `reports/eram_core_diag/`。

ISSI 旧 -7 模型的默认 tAC=5.5ns 和 7ns 最小时钟不对应本工程 SiP。该功能对照明确关闭 specify 检查，并将模型输出响应设为 1ns、行时序参数设为 0，仅用于观察命令、地址和突发功能；不能用它证明实际 SiP 接口或静态时序正确。TD 依旧保留完整 0°/180°关系和所有时序违例，交付仍为诊断候选。
