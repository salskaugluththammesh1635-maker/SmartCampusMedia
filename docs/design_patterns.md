# FPGA 设计范式速查（本项目实例索引）

> **用途**：读代码时先认出"它属于哪一类设计"，再读细节就快得多。
> 本项目 14 个代码文件恰好覆盖 8 种典型范式，可作为对照学习的样本集。
>
> 每个 `.v` 文件头部的【四、设计思路与范式】章节，就是对本文件的范式定位。

## 一、为什么先认范式

数字电路代码看起来"都是一堆 always 块"，但**设计意图差别极大**。认准范式，就知道该重点关注什么：

| 范式 | 读代码时重点看 |
|---|---|
| 组合译码 | 映射关系是否完整、有无 `default` 兜底 |
| 线性序列机 | 序列有多长、每步做什么、如何回到起点 |
| 有限状态机 | 有几个状态、转移条件、有无死锁或不可达状态 |
| 计数器/分频 | 分频比换算对不对、计满后的动作 |
| 打拍/移位 | 打几拍、为什么需要这些拍 |
| 并行阵列 | N 份逻辑是否真的互相独立 |
| 结构化装配 | 例化关系、连线是否正确 |
| 原语例化 | 参数配置是否符合手册 |

## 二、八种范式详解

### 1. 组合译码（Combinational Decode）

- **特征**：`always @(*)` + `case`/`if`，无时钟、无状态
- **本质**：一张**真值表**——输入变，输出立即变
- **写法要点**
  - 组合块内**只用阻塞赋值 `=`**
  - 必须有 `default` 分支兜底，否则综合出**锁存器（latch）**（多数场景是 bug）
  - 输出会带组合毛刺，纯组合信号不宜直接当时钟或异步复位用
- **本项目实例**
  - `rtl/common/seg_decoder.v` —— 4 位数字 → 7 段码，最纯粹的真值表
  - `rtl/video/test_pattern_gen.v` —— (坐标, 图案号) → RGB 颜色
  - `rtl/input/key_matrix_4x4.v` 的**块⑥ 优先级编码**（组合 always + for 展开）

### 2. 线性序列机（LSM, Linear Sequence Machine）

- **特征**：用一个计数器推进**固定序列**，状态转移**不依赖输入**（无条件）
- **本质**：一个循环的"秒表"——每一步做固定的事，走完一圈再从头
- **写法要点**
  - 统一写法：`if (cnt == MAX-1) cnt <= 0; else cnt <= cnt + 1;`
  - "当前步"就是计数器的值，直接拿来做译码
  - 常派生一个**节拍脉冲**（tick）驱动其他逻辑：`assign tick = (cnt == MAX-1);`
- **本项目实例**
  - `rtl/video/video_timing_gen.v` —— **最经典案例**。行计数器(0~799) 与场计数器(0~524)
    嵌套：行计满进位到场、场计满回到开头，构成"二维序列机"。理解了这个，视频时序就通了
  - `rtl/display/seg_scan4.v` —— `dig_idx` 0→1→2→3→0 循环点亮四位数码管
  - `rtl/input/key_matrix_4x4.v` —— `row_idx` 0→1→2→3 循环扫描键盘四行
- **与 FSM 的本质区别**：LSM 的下一步**唯一确定**；FSM 的下一步**由输入决定**

### 3. 有限状态机（FSM, Finite State Machine）

- **特征**：有状态变量；**转移条件依赖输入**；输出由状态（Moore）或状态+输入（Mealy）决定
- **写法要点**
  - 本项目采用**隐式 FSM**：状态变量就是 `mode`，转移写在优先级 `if-else` 链里
    （相比教科书的 `case(state)` 三段式写法，这种写法在状态少、转移条件简单时更直观）
  - 必须给状态变量**复位初值**，且 `case` 要有 `default`，避免进入未定义状态
  - 优先级链的顺序 = 业务优先级（本项目把"应急"放最高，是安全性设计）
- **本项目实例**
  - `rtl/control/player_ctrl.v` —— `mode ∈ {日常(0), 科普(1), 应急(2)}`，
    按 KEY3 循环切换、KEY15 直达应急；同时管理自动轮播定时器

### 4. 计数器 / 分频器（Counter / Divider）

- **特征**：计满翻转或归零，把高频时钟"降速"成节拍或方波
- **换算公式**（必须记牢）
  - 产生**节拍**（如 1ms 一次）：`DIV = f_clk / f_tick`
  - 产生**方波**（如 523Hz 音）：`HALF = f_clk / (2 × f_out)`（半周期计数，计满翻转）
- **本项目实例**
  - `rtl/audio/buzzer_tone.v` —— `HALF_C5 = CLK_FREQ_HZ/(2*523)` 得到 C5 音
  - `rtl/display/seg_scan4.v` —— `SCAN_DIV` 产生 1kHz 扫描节拍
  - `rtl/input/key_matrix_4x4.v` —— `SCAN_DIV` 产生 1ms 行扫描节拍
- **参数化好处**：本项目把 `CLK_FREQ_HZ` 写成 parameter，50MHz 换 25MHz 时**逻辑一行不用改**

### 5. 打拍 / 移位（Pipeline & Synchronizer）

- **特征**：多级触发器串联，每拍把数据往后推一级
- **三类典型用途**
  1. **跨时钟域同步**：两级触发器消除亚稳态（`col_s0/col_s1`）
  2. **复位同步释放**：异步置位 + 同步撤除（`rst_sync`），避免复位释放时刻的亚稳态
  3. **边沿检测**：把信号打一拍再与当前值比较，找出上升/下降沿
- **本项目实例**
  - `rtl/top/dmz_eg4s20_hdmi_top.v` 的 `rst_sync[2:0]` —— 异步置位、同步释放
  - `rtl/input/key_matrix_4x4.v` 的 `col_s0/col_s1` —— 两级同步
  - `rtl/input/key_matrix_4x4.v` 的 `col_stable_d` + `press_edge` —— 按下沿检测
- **关键公式**：`press_edge = col_stable & ~col_stable_d` （当前为 1 且上一拍为 0 = 上升沿）

### 6. 并行阵列（Parallel Array）

- **特征**：同一逻辑复制 N 份，用 `for` 循环或 `generate` 展开
- **重要认知**：**FPGA 里的 `for` 循环不是"省硬件的循环"，而是"写代码时的复制粘贴"**——
  综合时会完全展开，每一份都是真实的独立寄存器
- **本项目实例**
  - `rtl/input/key_matrix_4x4.v` 的 16 个逐键消抖计数器
    （`db_cnt[k*4 +: 4]`，一个 64 位向量里塞了 16 个 4 位计数器）
  - 用法技巧：`k[3:2]` 取行号、`k[1:0]` 取列号，把一维索引映射到二维矩阵

### 7. 结构化装配（Structural / Top-Level）

- **特征**：顶层只做**例化与连线**，不含算法逻辑
- **为什么这样设计**
  - 子模块可**单独仿真验证**（本项目每个模块都有独立 testbench 或已被整机 TB 覆盖）
  - 子模块可**跨工程复用**（`seg_decoder`/`seg_scan4`/`key_matrix_4x4`/`buzzer_tone`
    同时被最小系统工程和 HDMI 工程使用）
  - 换顶层不影响子模块，降低改动风险
- **本项目实例**
  - `rtl/top/dmz_eg4s20_min_top.v`（最小系统）/ `dmz_eg4s20_bringup_top.v`（预演）/
    `dmz_eg4s20_hdmi_top.v`（HDMI）
  - `rtl/video/hdmi/hdmi_tx.vhd` —— 纯端口映射的 VHDL 适配层（语言桥接）

### 8. 原语例化（Primitive Instantiation）

- **特征**：不写逻辑，直接**配置芯片的硬核资源**
- **本项目实例**
  - `rtl/video/hdmi/hdmi_pll.v` —— 配置硬核 PLL（`EG_PHY_PLL` + `EG_LOGIC_BUFG`）
- **注意**：原语名与参数**和器件系列强绑定**（EG4/SF2 用 `EG_PHY_PLL`、
  `SF2_LOGIC_HS_OSERDES` 等）。换芯片系列必须查对应手册，不能照抄

## 四、选范式的决策路径

```
① 输出需要随输入"立即"变化、且不需要记忆？
   └─ 是 → 【组合译码】 always @(*) + case（记得写 default）
   └─ 否 ↓
② 需要按固定顺序循环做几件事？（顺序与输入无关）
   └─ 是 → 【线性序列机】 计数器推进 + 译码
   └─ 否 ↓
③ 下一步动作取决于输入 / 有明确的"模式"概念？
   └─ 是 → 【有限状态机】 状态变量 + 优先级 if-else 或 case
   └─ 否 ↓
④ 只是想要一个慢节拍或某个固定频率？
   └─ 是 → 【计数器/分频】 DIV = f_clk/f_tick 或 HALF = f_clk/(2·f_out)
   └─ 否 ↓
⑤ 需要隔离异步信号 / 找边沿 / 调时序？
   └─ 是 → 【打拍/移位】 两级同步器 / 延迟比较
⑥ 上面都不是 → 大概率你只是要【结构化装配】（把已有模块连起来）
```

**补充判断**：
- 同一逻辑要复制 N 份 → 加【并行阵列】（`for` 展开）
- 要用芯片硬核（PLL/SERDES/BRAM）→ 加【原语例化】（查手册）

## 五、本项目踩过的"范式相关"坑

| 坑 | 现象 | 教训 |
|---|---|---|
| 组合块里混用非阻塞赋值 | ① 安路 TD 直接报 `mixed blocking and non-blocking assignments` ERROR；② 仿真时 NBA 在时间步末覆盖阻塞赋值 → 数码管位选恒为全灭 | **组合用 `=`、时序用 `<=`，同一变量绝不在同一块内混用** |
| 同一变量被两个 always 块驱动 | 多驱动 → 综合报错；仿真出 X 态 | 一个状态变量**只由一个块负责**（本项目 `player_ctrl` 的 `auto_cnt` 曾踩此坑，用"单拍重置请求"解耦） |
| 线性序列机+条件更新的边界没想清 | 消抖计数器在非当前扫描行也被更新 → 永远归零，消抖彻底失效 | LSM 要明确：**什么节拍推进、推进时更新哪些**（本项目 `k[3:2] == row_idx` 就是这条约束） |
| 组合输出又打了一拍 | 整幅测试图向右偏移 1 像素 | 与 `de`/坐标同拍的像素必须**纯组合**输出，不能再寄存 |
| 时序块里用了组合赋值 | 在同一个块里既 `<=` 又 `=`，语义混乱 | 见第一条 |

## 六、给初学者的阅读建议

按"范式复杂度"排序读，而不是按文件名：

1. **组合译码** → `seg_decoder.v`（20 行，建立"无时钟逻辑"的概念）
2. **计数器分频** → `buzzer_tone.v`（理解 `f_clk/(2·f_out)` 的换算）
3. **线性序列机** → `seg_scan4.v`（4 步循环）→ `video_timing_gen.v`（二维序列）
4. **打拍** → `key_matrix_4x4.v`（两级同步 + 边沿检测）
5. **并行阵列** → `key_matrix_4x4.v`（16 个消抖计数器）
6. **有限状态机** → `player_ctrl.v`（三模式切换）
7. **结构化装配** → 三个顶层（看模块如何拼装成系统）
8. **原语例化** → `hdmi_pll.v`（查手册配置硬核）

配套的阅读顺序与自问清单见 `docs/reading_guide.md`。
