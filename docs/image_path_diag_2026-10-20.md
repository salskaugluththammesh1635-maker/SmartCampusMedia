# 完整图片通路分段观测

## 目的与已有证据

正式图片 bit 在真卡上完成装载（0010），但画面为全白，KEY15 应急红屏正常。独立 153600 字 SDRAM 自检已得到用户反馈：仅 LED0/1 常亮，整帧比对通过。

纯白现象尚未在行为模型中复现。连续自检通过不等于稀疏写入、完整仲裁和跨域显示读出均正确，因此本版本保持原图片通路，增加只读观测。它没有实施未经实机证据支持的功能修复。

## 上板操作与读数

使用原 SD 卡和 HDMI 接线，下载上述**完整通路诊断 bit**，按板卡复位，等待约 5 秒，报告四位数码管、哪些 LED 常亮以及画面。此次版本重新输出 HDMI、数码管和按键；不用修改 SD 图片。

数码管从左到右分别观察：

1. BMP 解码产生的 RGB565。
2. 实际被接受、DM=0 的 SDRAM 写命令数据。
3. SDRAM 控制器返回有效时的数据。
4. 有效显示区最终输出的 RGB565 像素。

每位是独立的粘滞标志：bit0 表示见过有效数据，bit1 表示见过精确红色 `F800`，bit2 表示见过非白色。0=没有有效数据；1=只见到白色；5=见到非白色但没有精确红色；7=见到精确红色。写/读同时检查一个字的两个半字。SDRAM 标志先锁存，再经两级同步进入像素域；每次装载共同复位。

| 读数 | 在当前白底红块素材上的解释 |
|---|---|
| 7777 | 四个边界均出现过红色，仍需结合最终视频 LED5 和实际画面 |
| 1111 | 解码边界已经只看到白色 |
| 7111 | 解码出现红色，写接口开始只看到白色 |
| 7711 | 写接口出现红色，读返回开始只看到白色 |
| 7771 | 读返回出现红色，最终像素开始只看到白色 |

这是“出现过”观测，不能证明位置、数量或整帧都正确。数字 5 或其他组合也应原样报告，不应强行归入上表。

实际板上反馈为 **7711，仅 LED0/1/2 常亮，无中央红块**。因此解码及 DM=0 写命令确实出现红色，但原显示读法的全部有效 SDRAM 返回只见白色，后续像素也只见白色；无 FIFO 和装载错误。此结果不能直接断言红像素已写进正确物理地址。下一步见 `docs/image_readback_diag_2026-10-20.md`。

此 bit 的 LED 定义再次不同：

| LED | 常亮含义 |
|---|---|
| 0 | 图片已提交（image_ready） |
| 1 | BMP 解码曾出现红色 |
| 2 | SDRAM 写命令曾出现红色 |
| 3 | SDRAM 有效读返回曾出现红色 |
| 4 | 最终有效 RGB565 像素曾出现红色 |
| 5 | 图片模式送入 HDMI 发送器的 RGB888 曾出现 FF0000 |
| 6 | 像素 FIFO 曾下溢或溢出 |
| 7 | SD 或图片装载失败 |

正常红块素材应为 7777、LED0～5 亮、LED6/7 灭。KEY15 的应急红屏不会设置 LED5；它只观察有效图片像素，重新装载时清除。

## 仿真边界

脚本实际检查白底红块的逐像素内容、有效性、完整帧和 FIFO 错误。小图用例还依次把解码、写命令、读返回和像素输出强制为白色，检查对应 1111、7111、7711、7771；之后加载合法白图验证没有旧标志残留。完整 640×480 用例检查原尺寸的中央 200×200 红块。故障注入用于验证观测能区分边界，**不代表复现了物理板的根因**。
