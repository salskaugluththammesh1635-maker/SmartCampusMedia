# 阶段四总体架构：SD 卡图片播放系统（BMP + FAT32 + SDRAM 帧缓冲）

> 状态：设计基线（v1，2026-10-17）。协议依据见 `docs/sd_spi_reference.md`（SD SPI + FAT32）与 `docs/eram_sdram_reference.md`（ERAM SDRAM）。
> 阶段三（HDMI 测试图案）已完全闭环；本阶段把「测试图案发生器」升级为「SD 卡 BMP 图片播放器」。

## 1. 系统数据流（目标态）

```
                25MHz clk_pixel（全逻辑主时钟域）          150MHz（新增，ERAM 专用）
┌──────────┐   ┌─────────────┐    512B 块流   ┌──────────────┐
│ SD 卡     │←─→│ sd_spi_ctrl │───────────────→│ fat32_reader │──图片像素流──┐
│ SPI 模式  │   │ (F15/F13/   │  CMD18 连续读  │ (FAT簇链解析) │             │
└──────────┘   │  F14/D14)   │               └──────────────┘             ↓
               └─────────────┘                                   ┌──────────────────┐
             初始化 400kHz→25MHz                                  │  wr_fifo (异步)   │═══→ ERAM SDRAM 控制器 (150MHz)
                                                                 └──────────────────┘         (官方 APUG011 加密核)
──────────────────────────── 显示路径 ──────────────────────────────────────
ERAM (150MHz 连续读流) ──→ rd_fifo(异步,跨到25MHz) ──→ rgb565 取像素 ──→ hdmi_tx
                                                                            ↓
test_pattern_gen（保留，模式0）— mux: pattern_sel=0 时显示测试图案，>0 时显示图片 ──→ HDMI 输出
```

按键：KEY0=上一张、KEY1=下一张、KEY3=暂停/恢复轮播（player_ctrl 已有模式框架，接入图库索引）；KEY4/5 保留切 pattern（含模式 0=测试图案兜底）。

## 3. 关键设计决策（已锁定）

1. **单 SD 卡驱动跑 25MHz 主时钟域**，SPI 输出用分频使能（init 390.6kHz = 25M/64，读数据 25MHz 直接满速），不引入第三个时钟。
2. **SDHC-only**（块寻址，512B/块）；CMD8 失败即报错停机，不做 SDv1 降级。
3. **素材只支持 640×480 24bit BMP**（其余尺寸跳过，数码管/LED 报错码）；命名 `IMG001.BMP…IMG999.BMP` 8.3 短名，只匹配短名跳过 LFN。
4. **像素格式：解码时 24bit RGB→16bit RGB565 进 SDRAM**（容量余 13 帧、带宽余 10×，均按 565 核算）；显示时直接从 SDRAM 读 16bit。
5. **读写互斥调度**：显示读流为连续主设备；写帧只在**帧消隐期**（v-sync 后沿至下一帧有效区开始）突发写入；写通道无反压，由调度器保证不撞刷新窗口（Sdr_init_ref_vld 避让）。
6. **帧缓冲单帧起步**（先跑通再优化双缓冲；撕裂效应单帧下表现为更新瞬间的一帧混屏，可接受，后续 ping-pong 消除）。
7. **错误上报**：SD init 失败/无卡/无图 → LED[3:0] 显示错误码 + 数码管 + 画面自动回落测试图案（pattern 0），保证「显示稳定性与鲁棒性」赛规项。
8. **SFT（Sdr_clk_sft）与 150MHz 主时钟**：由 hdmi_pll 扩展 C3/C4 输出（1000MHz VCO / C3=6.667 非——**不可行**；改用 VCO 重算：C3=C4 需 150MHz=1000/6.667 非整数 → **hdmi_pll 需重配 VCO 或第二颗 PLL**，见 §5 风险）。

## 5. 风险与预案

| 风险 | 影响 | 预案 |
|---|---|---|
| hdmi_pll 出不了 150MHz（1000MHz VCO 无整数分频） | SDRAM 无时钟 | 方案 A：hdmi_pll 改 VCO=1200MHz（50/2×48）→ C0=25(÷48) C2=150(÷8) 检查 5x=125 不再可得→方案 B：第二颗 PLL 专供 150M+180°（芯片 4 PLL，现用 1 颗）；**倾向方案 B**，且官方例程 clk_pll.v 本来就是独立 PLL |
| 加密核 license 在 headless 之外失败 | SDRAM 不可用 | 同 HDMI 核，已有解法先例 |
| 读写互斥调度 bug | 显示撕裂/花屏 | S5 切片先行单帧固定图案验证 |
| SD 卡型号兼容性 | 初始化失败 | 已按规范避开官方例程 7 缺陷；报错码可定位 |
| 模拟卡模型工作量 | S3 前仿真受阻 | 用「文件→$readmemh 预载扇区镜像」的轻量模型，不做全协议 |

## 6. 赛规对照（本阶段推进项）

- 基础① 核心功能完整性：SD 图片播放是「多媒体播放系统」的核心语义，本阶段直接补齐。
- 基础② 稳定性：错误回落机制 + SDRAM 刷新避让设计。
- 扩展② 图片切换转场：本阶段先把「切换」做出来（player_ctrl 已有），转场效果（淡入淡出等）属阶段五。
- 扩展③ 图片缩放适配：非 640×480 图暂跳过；缩放器列阶段五扩展。
