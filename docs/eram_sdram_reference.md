# SiP SDRAM（ERAM 接口）技术参考

> 2026-10-29 更新。官方底板 `7_SDRAM_as_BRAM` 例程与 APUG011 是接口来源；本文明确区分官方历史用法与当前 `rtl/storage/` 生产合同。当前工程入口和验收状态以 [README](../README.md)、[架构分析](../ARCHITECTURE.md)和[显示修复记录](display_fix_2026-10-29.md)为准。

## 1. 硬件容量与几何

| 项目 | 当前配置 |
|---|---|
| 器件 | EG4S20 封装内 `EG_PHY_SDRAM_2M_32`，不占板级 SDRAM IO |
| 容量 | 2M × 32 bit = 64 Mbit = **8 MiB** |
| 几何 | **4 bank × 2048 行 × 256 列 × 32 bit** |
| 接口位宽 | 数据 32、应用字地址 21、字节掩码 4、行地址 11、bank 地址 2 |
| 控制核 | 官方 APUG011 `sdr_as_ram` / `sdr_wrrd` / `sdr_init_ref`，保持原文件不改 |

容量由几何相乘核算；旧文档把列数写为 512，会错误地翻倍容量。当前引脚模型使用 8 位列地址，生产配置为 `ROW_WIDTH=11`、`BA_WIDTH=2`。应用层使用 21 位**32 bit 字地址**；bank、行、列的具体位切分属于核内部实现，不能只根据几何或历史注释推导后写成应用接口合同。

官方例程的资源数字（例如 TD5.6.2 在 EG4S-MINI-DEV3 上的 LUT 447、REG 96、Fmax 219 MHz）只是该例程的历史数据，不能代替本项目的面积和时序报告。

## 2. 生产分层

```text
image_player / pix_reader
    ↕ 57 bit 写 FIFO / 32 bit 读 FIFO，25 MHz ↔ 40 MHz
framebuf_arbiter          四字组、读优先防写饥饿、在飞计数、重启排空
    ↕ app_* / ref_vld / sdr_rd_*
sdram_ctrl_wrap          复位/命名适配、手动刷新调度、粘滞 refresh_error
    ↕ 官方接口
sdr_as_ram               官方核顶层，组合读写引擎与初始化/刷新模块
    ↕ SDRAM 命令 / 地址 / DQM / DQ
EG_PHY_SDRAM_2M_32        封装内 SiP SDRAM
```

官方 `app_wrrd` 是激励与校验范例，不在生产数据通路中。其自增测试、低 16 位比对方式以及自动刷新配置都不代表生产仲裁器的行为。

## 3. 官方端口与包装器接口

| 官方信号 | 方向/位宽 | 当前接法与约束 |
|---|---|---|
| `Sdr_clk` | in / 1 | **40 MHz 0°**，仲裁器和核同域；官方例程曾用 150 MHz |
| `Sdr_clk_sft` | in / 1 | 同频 **180°**，仅送 SDRAM 时钟接口 |
| `Rst` | in / 1 | 高有效；包装器把低有效 `rst_n` 取反 |
| `Sdr_init_done` | out / 1 | 初始化完成前禁止应用命令 |
| `Sdr_init_ref_vld` | out / 1 | 包装器接为 `core_ref`；上层使用扩展后的 `ref_vld`，包括排空、静默、握手和故障窗口 |
| `Sdr_busy` | out / 1 | 官方标注暂不使用，生产仲裁不以它判定接受 |
| `App_ref_req` | in / 1 | `self_refresh_open=0` 时由包装器发单拍手动请求 |
| `App_wr_en` / `App_wr_addr` | in / 1、21 | 无 ready；只在初始化完成且 `ref_vld=0` 时提交完整四字组 |
| `App_wr_din` / `App_wr_dm` | in / 32、4 | `dm[n]=1` 屏蔽对应字节；读取及空闲必须为 `4'h0` |
| `App_rd_en` / `App_rd_addr` | in / 1、21 | 与写互斥；四字组首地址对齐，生产组内保持同一基址 |
| `Sdr_rd_en` / `Sdr_rd_dout` | out / 1、32 | 仅在 valid 为高时接受返回；按真实返回维护在飞数 |

物理侧为 `SDRAM_CLK`、RAS/CAS/WE、BA[1:0]、ADDR[10:0]、DM[3:0]、DQ[31:0]；包装器保持 CKE=1、CS_n=0。这里的手动请求发出周期 AUTO REFRESH 命令，不是让 CKE 拉低进入 SDRAM 自刷新低功耗模式。

**DQM 同时影响读和写。** 真实写使用请求掩码；组内断流时用 `4'hF` 补拍且不消费写 FIFO；读和空闲置 `4'h0`。旧读期掩码导致白屏的修复及板端历史记录见 [DQM 修复](image_dm_fix_2026-10-20.md)。

## 4. 四字组与返回时序

1. 应用地址以 32 bit 字计数。一组有四个字、共 16 字节；组首低两位为 0。生产仲裁器在组内四拍保持组基址，由核推进组内字；完成后基址加 4。不能把它表述为“应用地址单位是 128 bit”，也不能把本项目的恒基址策略推广为所有官方驱动每拍低两位都必须为零。
2. 读写命令不能同拍发生，换向只在完整组边界进行。装载端至少收齐四个真实字后再启动写组；显示读优先，等待较久的写请求通过饥饿阈值获得服务。写入可与前台显示交错，不局限于消隐期。
3. 相邻读组首至少相隔 **13 个 SDRAM 周期（325 ns）**。真实核在特定 12 拍间隔会漏 ACT；门控只影响下一组首，不截断组内四拍。跨 bank/row 的最小复现和间隔扫描见[显示修复记录](display_fix_2026-10-29.md)。
4. 行为模型的固定读延迟为 10 拍，官方资料也给出名义读延迟说明；生产逻辑必须以 `Sdr_rd_en` 为准。返回信用、无进展看门狗与帧首重启握手防止迟到旧数据混入新帧。
5. 官方资料的高频连续写吞吐条件不能直接作为本项目 40 MHz 全程连续提交的保证。生产按完整组调度；有效吞吐还包含读组间隔、方向切换和刷新开销，整帧与真实 SPI 速率回归是当前验证依据。

## 5. 时钟与跨域

板载 50 MHz 参考驱动两颗独立 PLL：视频域为 25 MHz 像素和 125 MHz 串化，`sdram_pll` 为 **40 MHz 0°/180°**，两相均经 BUFG。25 MHz 负责 SD、FAT32、BMP 和像素消费；40 MHz 负责写 FIFO 读侧、仲裁器、控制核与读 FIFO 写侧。数据流用异步 FIFO，状态用同步器，生产/消费计数用 Gray 码。

同一 SDRAM PLL 的 0°/180°有确定相位关系，必须同组接受时序分析；只在两颗独立 PLL 之间分异步组。历史 150 MHz / 100 MHz 的 SiP 接口 setup 余量为负，当前降到 40 MHz；把两相拆异步得到的正余量不能作为修复证据。当前构建结果见 §9。

## 6. 统一配置与手动刷新

配置源为 [`ip/config/sdram/global_def.v`](../ip/config/sdram/global_def.v)，由 [`sync_src.ps1`](../scripts/sync_src.ps1) 同步到被 Git 忽略的 `ip/local/sdram/global_def.v`，以兼容官方核的相对 include。不要只改该本地副本。

```verilog
`define SDR_CLK_PERIOD (1000000000 / 40000000)
`define SELF_REFRESH_INTERVAL ((32000000 / (`SDR_CLK_PERIOD)) / (1 << (`ROW_WIDTH)))
```

当前周期 25 ns，`ROW_WIDTH=11`，刷新宏为名义 **625 拍**，减 10 后仍正确为 615。完整括号避免宏代入后改变运算优先级；旧宏曾实际算为 0。32 ms 是全行刷新请求预算，为器件 64 ms 保持要求预留调度余量；宏值不等于物理 AREF 的固定间隔。

当前 `sdram_ctrl_wrap` 关闭核内自动刷新（`self_refresh_open=0`），以 `CLK_FREQ_HZ / 64000` 计时：

1. 到期后等待读写组均结束，在组边界提前拉高 `ref_vld`，阻止新组进入。
2. 等已接受的读返回全部排空，再保持 **16 拍静默**。
3. 发单拍 `App_ref_req`，等待 `core_ref` 拉高再拉低，才清除到期标志并恢复应用命令。
4. 刷新握手看门狗或意外读返回置位粘滞 `refresh_error`，持续阻塞命令直到存储复位。握手计数先达到 1024，随后一个等待边沿置错。

这替代了官方范例的自动请求用法：真实核自动刷新与完整事务尾部交叠时仍可能产生间隔 25 ns 的双 AREF，违反 70 ns `tRC`，不能靠“见到刷新就中断事务”规避。排空、静默和握手过程均属于 `ref_vld` 窗口，不会中断已接受的完整组。

修改频率时必须同时核对 PLL、包装器 `CLK_FREQ_HZ`、统一配置头和各诊断工程实例；不得修改受保护核来绕过接口条件。

## 7. 当前双缓冲布局与故障恢复

| 项目 | 数值/行为 |
|---|---|
| 单帧 | 640×480 RGB565 = 307200 像素 = **153600 字 = 614400 B = 600 KiB** |
| 帧 0 / 帧 1 基址 | **0 / 153600**（32 bit 字地址）；对应字节偏移 0 / 614400 |
| 总占用 | 307200 字 = 1228800 B = 1200 KiB |
| 装载 | `back_sel=~front_sel`，写后台帧，显示继续读前台帧 |
| 提交 | 像素数完整且写命令完成后挂起，已有前台帧时在垂直消隐提交 |
| 重启 | `rd_base` 随前台选择更新；读组、在飞返回与 FIFO 排空后明确完成帧首重启 |

装载侧失败保留旧帧；仲裁、刷新或存储失锁使旧帧失效，内部错误码为 **8**。`image_player` 将 `refresh_error` 与仲裁错误同步进像素域；重试 `C_RESET` 且没有有效旧帧时允许残留同步值消退，有效旧帧仍受故障监视。`SEAMLESS=0` 仅作为单缓冲对照，不是生产默认。

## 8. 官方历史资料的使用边界

- 官方例程曾使用 150 MHz、自动刷新、特定连续写测试及低 16 位比较；这些是历史参考，不是当前频率、刷新或数据校验合同。
- 加密核需具备匹配的仿真器解密支持；当前真实核回归使用本机 Questa/AMS 环境，普通行为回归使用自研模型。编译成功不能替代数据正确性检查。
- 旧例程仿真时钟和 PDF 示例不完全一致，运行脚本还可能有作者本机绝对路径；复现应使用仓库脚本。
- 厂商引脚模型的时序违例须检查原因，不能以“仿真能跑”或关闭时序检查代替通过。当前真实核内容和保持回归保留数据手册时序参数并检查错误。

## 9. 当前证据与限制

冻结后真实核内容回归检查 614407 项且帧与原图完全一致；64 ms 保持后连续两次读回共 307200 字零错。保持测试物理 AREF 间隔 16650～16950 ns，64 ms 保持期 3843 条 AREF；刷新协议、排空、握手超时、粘滞保持和复位恢复另有五场景回归。来源及源码哈希见[正式证据索引](display_fix_2026-10-29.md#已有回归证据及覆盖边界)。

用户已确认正式显示修复版的板端异常解决。最新低音量版仍使用同一 40 MHz 存储合同；其[构建清单](../reports/hdmi_audio_quiet_20261029/manifest.json)记录 setup WNS +1.935 ns、hold WNS +0.003 ns、TNS 为 0、STA 覆盖率 99.87%。部分外部 IO 延迟约束与既有 PLL/SiP 告警仍待核查，低音量试听及完整板端验收尚待反馈。功能引脚模型不能验证 FPGA 实际 IO、电气、线缆或接收端。
