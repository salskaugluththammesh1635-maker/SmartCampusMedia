### 1.2 端口定义（TN304_1.3 第 1 页 表 1 + 第 3 页 §4.1，原文照录）

```
module EG_PHY_ADC (clk, pd, s, soc, eoc, dout);
    input        clk;   // ADC 工作时钟，fmax = 16MHz
    input        pd;    // ADC 低功耗掉电模式（power Down signal）
    input  [2:0] s;     // ADC 通道选择信号输入（channel Select Signal）
    input        soc;   // 采样使能信号输入，高有效（start of Conversion）
```

**TN304 第 3 页 表 4 关于 pd 的原文**：「power_down，**1'b0 正常工作**」——即 `pd = 1` 为掉电，`pd = 0` 为正常工作。

**参考电压实测接法**（核心板原理图第 2 页）：`ADC_VREF` = **L11**，经 **R101 = 22.1 Ω** 串阻 + **C57 = 0.1 µF** 去耦接到网络 `NLADC0VREF`，源为 Config02 的 `OUT_3.3V`。→ **VREF ≈ VDDA ≈ 3.3 V**，正好满足 TN304 第 2 页注意事项②「建议 VREF 设成 1.0 × VDDA」。
`ADC_VDDA` = **R13**，与 `VCCO_1`(N15) / `VCCO_2`(N10) / K13 同接 3.3 V → **BANK2 的 VCCIO = 3.3 V = ADC 模拟电源电压**，满足 TN304 第 1 页 §3「当使用 ADC 时，相关 BANK 的 VCCIO 电压应不低于 ADC 模拟电源电压」以及 1.2 版修订说明的同一条要求。

> **原理图实测补充（本条把「VCCO_2 与 ADC_VDDA 同接 3.3 V」从推断升级为图形级证据）**：核心板原理图第 2 页上，EG4S20 的全部电源脚被画进**同一个名为 `U7F`、标注 `POWER` 的符号框**（框体为 x ≈ 650 ~ 740、y ≈ 226 ~ 416 的矩形，由 `get_drawings()` 确认这两条竖线是该矩形的左右边框，**不是电源轨**，勿误读）。框内左列自上而下依次是 `VCCAUX`（E5 / F11 / F8 / G10 / H6 / J10 / L6 / L9）、`VCCO_0`（B13 / B4 / B9 / D10 / D7）、`VCCO_1`（G13 / J15 / K13 / N15）、**`ADC_VDDA`（R13）**、`ADC_VREF`（L11）、**`VCCO_2`（N10 / N7 / R4 / R8）**、`VCCO_3` 组；框的**左上角挂网络名 `FPGA3.3V`**（x ≈ 623, y ≈ 216），右上角挂 `FPGA1.2V`（x ≈ 745, y ≈ 216），后者只对应 `VCCINT` 那一列。
> → 结论之一（图形级）：**BANK2 的 VCCIO（VCCO_2，球 N10 等）与 ADC 模拟电源 ADC_VDDA（球 R13）同属 `FPGA3.3V` 电源域**，而 `VCCINT` 单独在 `FPGA1.2V` 域 → TN304「相关 BANK 的 VCCIO 电压应不低于 ADC 模拟电源电压」在本板上**硬件已满足，软件侧无需任何处理**。
> → 结论之二（区分两个 3.3 V 支路，勿混淆）：**ADC 参考源 VREF 不等同于 FPGA3.3V 网络**——VREF（球 L11）是从 `Config02` 符号的 `OUT_3.3V` 引脚经 **R101 = 22.1 Ω + C57 = 0.1 µF** 低通网络单独引出的 3.3 V 支路。二者同为 3.3 V 电平但**网络名不同**（`OUT_3.3V` vs `FPGA3.3V`），这正是 TN304 第 2 页注意事项①所要求的「准确、干净」的参考电压走法。
> （方法学提示：本页是**原理图 PDF 而非网表**，上述归属由「同一 POWER 符号内的引脚分组 + 网络标签位置」推定。若需 100 % 确定性，可在 t9 上板时用万用表实测 **R13 对地 3.30 V、N10 对地 3.30 V、L11 对地 3.30 V**——三点一次测完即闭环，风险等级：低。）

### 1.4 「与用户 IO 复用」到底意味着什么（逐条说清）

TN304 第 1 页 §3 原文：

> 「8 个通道输入和用户 IO 复用，当用户不需要 ADC 时可以当作普通用户 IO 使用，**复用 IO 设置相互独立**，未使用的 ADC 通道管脚可以作为普通 IO 使用。」

拆解为工程结论：

| 问题 | 答案 | 依据 |
|---|---|---|
| 占用哪些引脚？ | **只占用你使能的那几个通道对应的球**。参数里把 `CHn` 设为 `"ENABLE"` 的通道才占球；设为 `"DISABLE"`（默认值）的通道其球仍是普通用户 IO | TN304 第 3 页 表 3（Allowed Values: `"DISABLE"`/`"ENABLE"`，Default: `"DISABLE"`） |
| 本项目占几个球？ | **1 个**：`CH1` → 球 **M10**（核心板 P2 排针脚 31） | §1.3 表 |
| 要不要额外硬件？ | **不要**。ADC 在 FPGA 硅片内部，外部无需任何 ADC 芯片 | DS301 第 3 页「嵌入式硬核 IP」 |
| 要不要特殊 IP 核？ | **要，但只是原语生成**：必须用 TD 的 **IP Generator** 生成 `EG_PHY_ADC` 原语 | TN304 第 4 页 §4 原文：「用户可自身需要选择需要采样的通道，**通过 IP generate 的方法使用 ADC 模块**」 |
| TD 里怎么例化？ | 在 TD 的 IP Generator 中选 ADC 模块 → 勾选 CH1 = ENABLE、VREF = ENABLE（本项目用内部参考）→ 生成 `.v` 原语文件 → 加入工程 → 在 RTL 中实例化并驱动 clk/pd/s/soc，读 eoc/dout | TN304 第 3~4 页 §4 |
| 是否影响现有引脚约束？ | **不影响**。M10 当前在 `dmz_eg4s20_hdmi.adc`（99 行）中**完全未被占用**，新增一行即可 | `SmartCampusMedia/constraints/dmz_eg4s20_hdmi.adc` 全文核对 |
| 会不会影响已用功能？ | **不会**。BANK2 上本项目仅使用 `clk = R7`（`IO_TE11P_GCLKIOT_5_2`），其余 ADC 通道球均空闲 | `.adc` 与 DS301 第 19 页交叉核对 |

**关于 TN304 第 2 页注意事项③**「在用 ADC 的时候，尽量避免使用 ADC IO 相同 BANK 的数字 IO 以减小噪声」：本项目 BANK2 上只有 `clk`（50 MHz 全局时钟输入）一个数字信号，且为 GCLK 专用输入，翻转噪声远小于普通高速数据 IO。**风险可接受，且无替代方案**（clk 不可移出 BANK2，它是板上固定走线）。缓解措施见 §4.4。

## §2 采样时序设计（含 TN304 的两个坑）

### 2.1 坑一：SOC 间隔不能太大（TN304 第 4 页 §5 原文）

> 「建议 SOC 采样间隔要小于 10 us，即采样频率不要低于 100 KHz；若需要大间隔的采样，需要在 SOC 到来 5 个时钟周期前拉高一下 PD 脚之后再进行采样。」

**两个可选方案**：

| 方案 | 做法 | 优点 | 缺点 | 本项目选择 |
|---|---|---|---|---|
| **方案甲（推荐）** | **永远高速连续采样**：ADC 时钟 12.5 MHz，每 10 µs（100 kHz）发一次 SOC，从不停止；FPGA 内部对采样流做**数字抽取平均**得到所需更新率 | **完全避开 PD 时序坑**，不需要理解 PD 脉冲的确切语义；过采样带来额外 ~3 bit 等效精度提升（√N 律）；实现最简单 | 功耗略高（几 mW，可忽略） | ✅ **采用** |
| 方案乙 | 1 Hz 慢采样：每次 SOC 前 5 clk 给 pd 一个高脉冲唤醒，再 pd=0，再 SOC | 功耗最低 | PD 脉冲宽度/极性语义官方描述含糊（表 4 说 `pd=1` 是掉电，正文却说「拉高一下 PD 脚之后再进行采样」），有踩坑风险 | ❌ 不采用 |

**方案甲的具体参数**：
- ADC 时钟 `adc_clk` = 50 MHz ÷ 4 = **12.5 MHz**（满足 ≤16 MHz 上限，留 22% 余量）
- SOC 周期 = 125 个 `adc_clk` = **10 µs** → 采样率 **100 kHz**（正好等于 TN304 建议下限，安全）
- 抽取平均 N = 4096 → 有效更新率 = 100 kHz / 4096 ≈ **24.4 Hz**（远快于 1 Hz 需求）
- 等效位数提升 = log₂(√4096) = **+6 bit** 理论（实际受限于模拟前端，取保守 +2~3 bit 有效提升）
- 抽取实现：一个 24 bit 累加器 + 一个 16 bit 计数器，**约 40 LUT**，无需 BRAM

### 2.2 坑二：EOC 与 DOUT 的采样时机

TN304 第 2 页 图 2 给出 EAGLE ADC 采样控制时序。保守实现（不依赖对图 2 的精确解读）：

```
状态机：
  IDLE   → 等 soc_tick（10µs 到）→ 拉高 soc 一个 clk → 进 WAIT_EOC
  WAIT_EOC → 等 eoc 上升沿 → 进 CAPTURE；超时 64 个 clk 未等到 → 记 fault，回 IDLE
  CAPTURE  → 在 eoc 上升沿后 2 个 clk 采 dout[11:0] 存入 acc → 回 IDLE
```

- **超时保护**：EOC 超时 64 clk（5.1 µs）未到 → 置 `adc_timeout` 标志，不更新结果，保持上次有效值。
- **数据有效性判定**：`dout` 落在 **410 ~ 3686**（0.1~0.9 × VREF 对应码值，见 §3.3）之外 → 判「超量程/传感器故障」，不使用该值。

## §3 NTC 10 kΩ 热敏电阻 + 分压电阻 选型与计算

### 3.1 器件选型

| 器件 | 参数 | 选型理由 | 单价（参考） |
|---|---|---|---|
| NTC 热敏电阻 | **10 kΩ @ 25 ℃，B 值 = 3950 K，±1%**，0603 或直插 | 10 kΩ@25℃ 是最通用规格，货源充足；B=3950 是标准值；±1% 精度使 45 ℃ 处误差仅 −0.21 ℃ | ¥0.1 ~ 0.5 |
| 分压上拉电阻 | **10 kΩ，±1% 金属膜**，0603 或直插 | 与 NTC 的 25 ℃ 阻值相等 → 25 ℃ 时 V = VREF/2，正好落在 ADC 量程正中，量程利用率最高 | ¥0.02 |
| 接线 | 杜邦线 3 根（3.3V / 信号 / GND） | 信号 = 核心板 P2 排针**脚 31**（ADC_CH1）；3.3V 与 GND 取电脚须上板实测（见 §1.3 说明） | 已有 |

**电路拓扑**（NTC 作为下臂）：

```
        OUT_3.3V (取电脚，上板实测确定)
             │
          [ Rp = 10kΩ ±1% ]
             │
             ├──────→ ADC_CH1 (球 M10, 排针脚31)
             │
          [ NTC 10kΩ B=3950 ]
             │
            GND (取电脚，上板实测确定)
```

### 3.2 传递函数与反解公式

**正向（温度 → 电压）**：

$$R_{ntc}(T) = R_{25}\cdot \exp\!\left[B\left(\frac{1}{T} - \frac{1}{T_{25}}\right)\right], \quad T_{25} = 298.15\ \text{K}$$

$$V(T) = V_{REF}\cdot\frac{R_{ntc}(T)}{R_p + R_{ntc}(T)}, \quad V_{REF} = V_{DDA} = 3.3\ \text{V}$$

**反解（电压 → 温度）**：

$$R_{ntc} = \frac{V\cdot R_p}{V_{REF} - V}, \qquad T(^\circ C) = \frac{1}{\dfrac{1}{T_{25}} + \dfrac{\ln(R_{ntc}/R_{25})}{B}} - 273.15$$

### 3.4 量化分辨率（有完整计算过程）

**12 bit 域**（ADC 原始输出）：

$$\text{LSB}_{12} = \frac{V_{REF}}{2^{12}} = \frac{3.3}{4096} = 0.8057\ \text{mV}$$

温度分辨率 = LSB ÷ |dV/dT|：

| 温度点 | \|dV/dT\| (mV/℃) | 12 bit 温度分辨率 (℃) | 8 bit 温度分辨率 (℃) |
|---|---|---|---|
| 0 ℃ | 30.87 | 0.8057 / 30.87 = **0.026** | 12.891 / 30.87 = **0.418** |
| **25 ℃** | 36.66 | 0.8057 / 36.66 = **0.022** | 12.891 / 36.66 = **0.352** |
| **45 ℃** | 27.20 | 0.8057 / 27.20 = **0.030** | 12.891 / 27.20 = **0.474** |
| 60 ℃ | 18.73 | 0.8057 / 18.73 = **0.043** | 12.891 / 18.73 = **0.688** |
| 70 ℃ | 14.09 | 0.8057 / 14.09 = **0.057** | 12.891 / 14.09 = **0.915** |

其中 $\text{LSB}_8 = 3.3/256 = 12.891\ \text{mV}$（按 TN304「有效精度 8 bit」的最坏情况算）。

**结论**：
- 按 **12 bit 原始码**使用（推荐）：45 ℃ 附近分辨率 **0.030 ℃**，比 5 ℃ 迟滞带精细 167 倍，绰绰有余。
- 即使按 **8 bit 有效精度**（最坏情况）：45 ℃ 附近分辨率 **0.474 ℃**，仍比 5 ℃ 迟滞带精细 10.5 倍，**完全够用**。
- 叠加 §2.1 的 4096 点过采样平均后，随机噪声进一步降低 √4096 = 64 倍，实际可用分辨率优于上表。

### 3.5 阈值与迟滞（12 bit 码值域，注意方向）

| 阈值 | 温度 | 12 bit 码 | 说明 |
|---|---|---|---|
| 触发超温 | **≥ 45 ℃** | `code ≤ 1241` | **注意：码值随温度升高而减小** |
| 解除超温 | **≤ 40 ℃** | `code ≥ 1419` | 迟滞带 = 1419 − 1241 = **178 codes** |
| 备用（更宽迟滞） | ≤ 35 ℃ | `code ≥ 1614` | 迟滞带 373 codes |
| 备用（更窄迟滞） | ≤ 42 ℃ | `code ≥ 1346` | 迟滞带 105 codes |

**RTL 判据（方向绝不能写反）**：

```
超温触发： if (temp_code <= 12'd1241) overtemp <= 1'b1;
超温解除： if (temp_code >= 12'd1419) overtemp <= 1'b0;
（中间 1242~1418 保持原状态 —— 这就是迟滞）
```

**迟滞带的抗噪能力**：45→40 ℃ 对应电压差 **143.29 mV**，是 12 bit LSB（0.806 mV）的 **178 倍**，是 8 bit 有效 LSB（12.891 mV）的 **11.1 倍** → 即使按最坏的 8 bit 精度，迟滞带仍有 11 个码的宽度，**不会因量化抖动误触发**。

### 3.7 故障自检（可区分三种故障）

| 故障 | 电路表现 | ADC 码值 | 判定逻辑 |
|---|---|---|---|
| **NTC 开路**（断线/虚焊） | 分压点被 Rp 拉到 VREF | **4095**（饱和上限） | `code > 3686` → 超量程高端 → `sensor_fault = 1` |
| **NTC 短路** | 分压点被拉到 GND | **0** | `code < 410` → 超量程低端 → `sensor_fault = 1` |
| **正常但极冷**（< −17.4 ℃） | 分压点接近 VREF | 3686 ~ 4095 | 与开路无法区分 → 保守判 `sensor_fault = 1` 并提示「温度低于量程下限」 |
| **上拉电阻开路** | 分压点悬空/被 NTC 拉到 GND | 0 附近 | 同短路 |

**设计决策**：故障时**不触发应急模式**，只置 `sensor_fault = 1` 并在 OSD 上显示「温度传感器异常」；应急模式仍可由 **Key3 手动直达**（C5 约束）。这样避免「传感器故障导致误报火灾」的荒谬场景。

## §4 与 AHT20 的接口对齐（上层逻辑零改动）

### 4.1 统一数据源接口定义（关键设计）

**设计目标**：让上层「阈值 → 迟滞 → 模式联动 → OSD」模块**完全不知道**温度数据来自 AHT20 还是 NTC+ADC。做到这一点只需要统一 4 根数据信号（另加 `clk` / `rst_n` 两个通用端口）。

```
// 统一的温度数据源接口（AHT20 与 NTC+ADC 两个实现都必须满足）
module temp_source_if (
    input  clk,               // 系统时钟
    input  rst_n,
    output reg signed [15:0] temp_centi_c, // 温度，单位 0.01 ℃（16 位补码）：25.00 ℃ = 16'sd2500
    output reg        temp_valid,  // 数据有效（有一帧成功测量且 CRC/量程检查通过）
    output reg        sensor_fault,// 传感器故障（CRC 连续失败 / 超时 / 超量程）
    output reg        meas_tick    // 测量完成单拍脉冲（供上层锁存）
);
```

### 4.2 两个实现的映射关系

| 统一信号 | AHT20 实现 | NTC + ADC 实现 | 上层是否感知差异 |
|---|---|---|---|
| `temp_centi_c[15:0]` | 20 bit 原始码 → `T = raw×200/2²⁰ − 50` → 转 0.01 ℃ 定点 | 12 bit 码 → 查表/分段线性 → 转 0.01 ℃ 定点 | **否** |
| `temp_valid` | 6 字节读完 + CRC8 通过 + 状态位 bit3=1 | 4096 点累加完成 + 码值在 410~3686 内 | **否** |
| `sensor_fault` | 连续 3 次 CRC 失败 或 I²C 超时 | 码值超量程 或 EOC 超时 | **否** |
| `meas_tick` | 每次测量完成 | 每次抽取平均完成 | **否** |
| 更新周期 | ≥ 1 s（I²C 100 kHz + 80 ms 转换） | 100 kHz / 4096 ≈ 24.4 Hz（再分频到 1 Hz 供上层） | **否**（上层按 1 Hz 节拍用） |

### 4.3 温度定点格式约定（两个实现必须一致）：`temp_centi_c`，单位 0.01 ℃

**格式**：`signed [15:0]`，单位 **0.01 ℃**，量程 **−327.68 ~ +327.67 ℃**，实际使用区间 **−50.00 ~ +149.99 ℃**。

| 温度 | 编码（16 位补码） | 十进制 |
|---|---|---|
| −50.00 ℃（AHT20 量程下限） | `16'hEC78` | −5000 |
| −10.50 ℃ | `16'hFBE6` | −1050 |
| 0.00 ℃ | `16'h0000` | 0 |
| 25.00 ℃ | `16'h09C4` | 2500 |
| 40.00 ℃（迟滞解除阈值） | `16'h0FA0` | 4000 |
| 45.00 ℃（超温触发阈值） | `16'h1194` | 4500 |
| +85.00 ℃（AHT20 标称上界） | `16'h2134` | 8500 |
| +149.99 ℃（AHT20 量程上限） | `16'h3A97` | 14999 |

> **【为什么不是 Q8.8】Q8.8 在 AHT20 满量程会溢出，这不是命名偏好。** AHT20 输出 20 bit 原始码 `raw ∈ [0, 1048575]`，`T = raw×200/2²⁰ − 50` → 对应 **−50.00 ~ +149.99 ℃**；而 Q8.8（16 位有符号，整数 8 位 + 小 8 位）量程只有 **−128.00 ~ +127.996 ℃**。`raw = 1048575`（满量程）换算成 Q8.8 应为 +149.9998 ℃ × 256 = **38400**，超出 16 位有符号上限 32767 → 截断后存成 `0x9600`（四舍五入）或 `0x95FF`（向下取整）= **−27136 / −27137**，**符号翻转**。**后果**：一旦 raw 越界（CRC 错、I²C 噪声、传感器脱焊、数据手册外工况），`temp_q8_8` 变负 → `if ($signed(temp_q8_8) >= 16'sh2D00)` 不成立 → **高温不触发应急模式，安全功能静默失效**，比误报更危险。`temp_centi_c` 量程 −327.68 ~ +327.67 ℃，对 −50~+150 ℃ 留 2.2 倍余量，全域安全。

**换算实现（AHT20 侧，含位宽陷阱）**：`20000 / 2²⁰ = 625 / 2¹⁵` 精确相等（`20000 = 625 × 32`、`2²⁰ = 2¹⁵ × 32`，**零舍入**），故

```verilog
// raw ∈ [0, 1048575]（20 bit）；raw*625 最大 655,359,375 = 0x270FFD8F，需 30 位
wire [29:0] t_mul = ({10'd0, raw} << 9) + ({10'd0, raw} << 6) + ({10'd0, raw} << 5)
                  + ({10'd0, raw} << 4) + {10'd0, raw};           // raw*625 = raw*(512+64+32+16+1)
wire [14:0] t_cen = t_mul[29:15];                                  // (T+50)*100 ∈ [0, 19999]
wire signed [15:0] temp_centi_c = $signed({1'b0, t_cen}) - 16'sd5000;  // −5000 .. +14999
```

- 625 = `2⁹+2⁶+2⁵+2⁴+1` → 4 次移位 + 4 次加法 + 1 次减法，**零 DSP、约 60~80 LUT**（比 Q8.8 版还少，因为不用做补码符号扩展）。
- **位宽必须是 `[29:0]`**：写成 29 位 `[28:0]` 会在满量程截断，`[28:15]` 取出 3615 而非 19999，报 **−13.85 ℃ 而非 +149.99 ℃**——与改用 0.01 ℃ 想避免的失败方向一模一样。
- 全覆盖实测（已逐点核对）：`raw=0 → −5000`（−50.00 ℃）／`52428 → −4001`（−40.01 ℃）／`524288 → +5000`（+50.00 ℃）／`707790 → +8500`（+85.00 ℃）／`1048575 → +14999`（+149.99 ℃）。
- **实现注记**：`>>15` 向下取整会使负温偏 0.01 ℃（−40.0002 ℃ 报 −40.01 ℃），**不为此加舍入逻辑**——AHT20 本身 ±0.3 ℃，这一位在噪声里。

### 4.4 上层「阈值 → 迟滞 → 联动」模块（两个方案共用，完全不改）

```
// 这一段代码 AHT20 与 NTC+ADC 完全共用，切换数据源时无需任何改动
localparam signed [15:0] TH_HIGH = 16'sd4500;   // 45.00 ℃ 触发
localparam signed [15:0] TH_LOW  = 16'sd4000;   // 40.00 ℃ 解除

always @(posedge clk or negedge rst_n) begin
    if (!rst_n) overtemp <= 1'b0;
    else if (meas_tick && temp_valid && !sensor_fault) begin
        if (temp_centi_c >= TH_HIGH)      // ≥ 45.00 ℃
            overtemp <= 1'b1;
        else if (temp_centi_c <= TH_LOW)  // ≤ 40.00 ℃
            overtemp <= 1'b0;
        // 40 ~ 45 ℃ 之间保持原状态 = 迟滞（5 ℃ 带 = 8.6 倍误差预算）
    end
    // 故障时保持原状态，不误触发应急模式
end

// 模式联动：超温 → 强制应急模式（与 Key3 手动直达同一入口）
wire emergency_req = key3_manual_press | (overtemp & emergency_enable);
```

### 4.5 切换成本量化

| 切换动作 | 工作量 | 说明 |
|---|---|---|
| 新增/替换数据源模块 | 1 个文件 | `aht20_temp_source.v` ↔ `ntc_adc_temp_source.v` |
| 顶层实例化改名 | 1 处 | 模块名 + 端口名（端口完全相同） |
| 引脚约束 | 2 行（AHT20：D1/E1）↔ 1 行（NTC：M10） | `.adc` 文件 |
| 上层逻辑改动 | **0 行** | 完全复用 |
| 重新综合时间 | 约 1 次 | — |

**结论：切换成本 ≈ 15 分钟的编辑 + 1 次 TD 综合。**

| 自热补偿 | **不需要** | §3.6(b) 已算：≤ 0.27 ℃，可忽略 |
| VREF 校准 | **不需要** | 核心板 VREF 直接取 OUT_3.3V，且 TN304 只要求 ±0.2% |
| 单点标定（可选） | **建议做但不强制** | 用室温计读一次实际温度，在 RTL 里加一个小的偏置常数即可消除系统性偏差（约 1 行代码） |
| **AHT20 需要校准吗** | **不需要** | 出厂已校准，直接输出可用值 |

**这是 Plan B 相对 AHT20 的唯一实质劣势**：Plan B 是「原始物理量 → 需自己线性化」，AHT20 是「出厂已校准 → 直接给温度」。但本项目只需 5 ℃ 精度的阈值判断，Plan B 的精度绰绰有余。

### 5.4 答辩说服力评估

| 维度 | AHT20 方案 | NTC + 片内 ADC 方案 |
|---|---|---|
| 合规性 | 需论证（本文档配套 A 已论证为合规，但评委可能仍有疑问） | **零疑问**——ADC 是 FPGA 内部硬核，外部只有两个电阻 |
| 技术含量叙事 | 「外接传感器模块」（听起来像拼装） | **「用 FPGA 片内 ADC 采集模拟信号并自主线性化」**（听起来像真做工程） |
| 与赛题契合度 | 中（赛题强调「算法在 FPGA 内」） | **高**（过采样平均、分段线性化、迟滞状态机全是 FPGA 内算法） |
| 现场可演示性 | 中（需用手捂热/吹气） | **高**（可用打火机远距离烘烤、或热风枪，NTC 响应快且耐高温） |
| 精度 | ±0.3 ℃ | ±0.58 ℃ |
| 接线复杂度 | 4 线（VCC/GND/SCL/SDA） | 3 线（3.3V/GND/信号） |
| 成本 | ¥5 ~ 15 | < ¥0.6 |

**意外的结论**：**Plan B 在「答辩说服力」这一项上反而优于 AHT20**——因为它更能体现「算法在 FPGA 内自主实现」这一赛规核心要求。这也是为什么推荐**两者同时实现**：AHT20 提供高精度与「智能传感」叙事，NTC+ADC 提供「片内硬核 + 自主算法」叙事，双数据源冗余还能现场演示「热备份切换」。

## §7 一句话结论

> **默认用 AHT20（精度高、免校准、叙事完整），同时把 Plan B（EG4S20 片内 SAR ADC + NTC 10 kΩ）实现并接好线，两者共用同一套上层「阈值 → 迟滞 → 联动」逻辑。触发切换的条件是：①~~AHT20 官方规格书最终无法获取（举证链断裂）~~ **已于 2026-11-01 关闭，手册到位**；②评委对 AHT20 合规性仍有异议；③AHT20 模块缺货或损坏；④（新增）评委不接受 p.15 免责条款的口径且要求彻底回避该器件。四个条件任一成立，改 1 个模块实例化 + 2 行引脚约束即可完成切换，上层零改动。**

**Plan B 的独立价值**：它在「体现算法在 FPGA 内自主实现」这一赛规核心维度上，叙事强度**高于** AHT20——因为 ADC 是 FPGA 硅片内的硬核，从模拟电压到温度值的全部处理（过采样平均、分段线性化、0.01 ℃ 定点换算、迟滞状态机）都在 Verilog 里。**建议两者都做，做双数据源热备份，答辩时现场演示切换。**
