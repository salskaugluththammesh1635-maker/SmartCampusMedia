## §3 为什么仍然推荐 AHT20 作主数据源（而不是全押 NTC）

对比表上 NTC+ADC 占优，但推荐仍以 AHT20 为主，理由有三：

1. **精度优势是确定的，合规风险是可消除的**。AHT20 的「中」风险来自**材料是否齐备**这一外部条件，而非技术本身——**规格书已于 2026-11-01 到位**（见 §4 T1），再补实物照片 + 接线图即可压到「低」。而 NTC 的精度劣势（±0.58 vs ±0.3 ℃）是**固有物理成本**，无法消除。（注：资源开销上 NTC+ADC 反而略省，约 230~380 vs 300~450 LUT，见 PLAN_B §5.1——这是 NTC 方案的加分项，不足以改变主备定位。）
2. **AHT20 免校准，Plan B 需要自己做线性化**。虽然本项目 5 ℃ 迟滞带对 ±0.58 ℃ 绰绰有余，但「出厂已校准」在答辩时是一个干净的说法，不需要解释「我为什么相信这条折线」。
3. **双数据源的叙事价值最大化**。AHT20 讲「智能传感与多源信息融合」（对应赛规 1.3「多源信息融合」），NTC+ADC 讲「片内硬核 + 自主算法」。**两个都做，两种叙事都拿到**，且能现场演示「主传感器拔掉 → 自动切备份 → 系统继续工作」的鲁棒性，这是评委爱看的。

## §6 关键数字速查（答辩现场可能被问到）

| 问题 | 答案 |
|---|---|
| AHT20 精度？ | ±0.3 ℃（典型） |
| Plan B 精度？ | ±0.58 ℃ 综合（RSS，√(0.47²+0.23²+0.015²+0.24²+0.0735²)=0.5805），45 ℃ 处元件容差 ±0.47 ℃ |
| Plan B 45 ℃ 温度分辨率？ | 12 bit 域 **0.030 ℃**；8 bit 有效精度域 **0.474 ℃** |
| 迟滞带多宽？ | 5 ℃（45 → 40 ℃），对应 12 bit 码差 **178 codes**，是 8 bit LSB 的 11.1 倍 |
| NTC 有效测温范围？ | **−17.41 ℃ ~ +84.28 ℃**（受 ADC 0.1~0.9×VREF 输入窗口限制） |
| 为什么上拉选 10 kΩ？ | 高温端覆盖到 84 ℃；选 15 kΩ 会让 80 ℃ 跌破 0.1×VREF 下限 |
| 自热误差？ | ≤ 0.27 ℃（25 ℃ 时功耗 0.272 mW） |
| Plan B 占多少 LUT？ | 230~380（占余量 4512 的 5.1%~8.4%）；两者同时实现 530~830（11.7%~18.4%） |
| Plan B 成本？ | **< ¥0.6**（2 个元件） |
| ADC 参数？ | 8 通道 / 12 bit 输出 / **8 bit 有效精度** / 1 MSPS / 时钟 ≤16 MHz / 输入 0.1~0.9×VREF |
| ADC 是外挂芯片吗？ | **不是**。是 EG4S20 硅片内的硬核 IP（DS301 第 3 页「嵌入式硬核 IP · ADC」） |
| 用哪个 ADC 通道？ | **CH1 = 球 M10 = 核心板 P2 排针脚 31**（CH0 = N11 未引到排针，不可用） |
| AHT20 换算对不对，怎么验？ | 用**手册 p.12 官方示例**做黄金向量：`ST = 0x2FFAB`（十进制 196523，20 bit）→ 手册浮点式 `T = (196523/2²⁰)×200 − 50 = −12.5162 ℃`（**手册展示为「−12.5 ℃」是四舍五入到 0.1 ℃，不是定点期望值**）。RTL 定点式 `raw×1250 >> 16 − 5000` 得 `3748 − 5000 = −1252`，即 **−12.52 ℃**。**注意不是 −1250**——把「−12.5」当「−12.50」直接乘 100 会漏掉真实值的 0.0162 ℃ 尾巴 |
| AHT20 精度与工作范围？ | 精度误差典型 **±0.3 ℃**、重复性 ±0.1 ℃、迟滞 ±0.1 ℃、分辨率 0.01 ℃、响应时间 τ63% 5~30 s、**工作范围 −40~120 ℃**（手册 p.3 表3） |
| AHT20 多久采一次？ | **1 s / 次**。手册 p.6 §2.3 要求「采集数据周期应大于 1 秒/1 次」，RTL `PERIOD_CYCLES = 25_000_000`（@25 MHz = 1 s）正好符合 |
| AHT20 的 I²C 跑多快？ | **100 kHz**（实测 99.2 kHz，`QUARTER = 25e6/(4×63)`）。手册 p.6 建议 10K~400KHz，落在区间内 |
| 手册说什么情况会读错？ | 手册 p.11 注：发出 `0xAC 0x33 0x00` 后**未等满 80 ms**，状态字 Bit[7] 可能仍为 1，此时读到的是上一次的数据。RTL `MEAS_WAIT_CYCLES = 2_000_000`（@25 MHz = 80 ms）已覆盖 |
| AHT20 上电要等多久？ | 手册 p.7 注 2：**5 ms 后**才可拉高 SCL/SDA。RTL 取 `POWERUP_CYCLES = 2_500_000`（100 ms，20 倍余量） |
| 手册有没有说不能用在安全装置？ | **有，p.15 明文「勿将本产品应用于安全保护装置或急停设备上」。** 本系统定性为教学演示装置；AHT20 只是触发入口之一，Key3 手动入口是独立冗余通道；对外统一称「**应急疏散引导演示**」。完整口径见 AHT20_COMPLIANCE_PACK §8 / §6 Q6 |
| 手册表9 的「校准计算使能」算不算它在算东西？ | 不算。是**固定多项式硬件补偿**，不可编程、不可配置、连器件自己都允许主机把 Bit[3] 置 0 直接输出 ADC 原始码。判据是「能不能换一个程序让它做别的事」。完整口径见 AHT20_COMPLIANCE_PACK §2 A8 / §6 Q5 |
