## 0. 一句话结论

问题 1 与问题 4 是**同一条通路上的三个独立缺陷叠加**，不是"日常模式少接了一根线"：

| 编号 | 缺陷 | 后果 | 本次是否修复 |
|---|---|---|---|
| **R1** | `audio_src_mux.v` 三个 8.3 短名常量**字节序写反** | FAT32 查找必然失败 → `err_code=6` → WAV 永不播放，三个模式全静音 | ✅ F1 |
| **R3** | `wav_stream_player.v` 16bit→24bit 用**符号扩展**而非左对齐 | 只在 24bit 满幅的 1/256 处出声（−48.16 dB） | ✅ F3 |
| **R4** | 顶层 `HDMI_AUDIO_ATTEN_SHIFT = 6` | HDMI 侧再压 1/64（−36.12 dB） | ✅ F5 |
| **R5** | 波形层的幅度换算依赖「输入是 24bit 满幅」这个前提，而 R3 破坏了它 | 波形恒为 1..2 像素直线 | ✅ F4（重构，行为等价）+ **实质靠 F3** |
| **R6** | `playback_state` 被钉 `ST_FAIL` 时 `tone_gen` 也静音 | 卡有问题时"连提示音都没有" | ⚠ **已知，本次不改**（见 §5） |
| — | `wav_stream_player.err_code` 顶层空连接 | 上板"没声音且无任何提示"，无法定位 | ✅ T2（可观测性） |

修好 R1+R3+R4 之后，日常/科普各模式的 WAV 才第一次真正出声；修好 R5 之后波形才能以 24bit 全精度入史；T2 保证下次再出问题时数码管会直接告诉你原因。

> **⚠ 关于 R5 的实测修正（2026-11-03 22:02，`tb_wave_ab.v`）**：本文档初稿把「波形恒为 1 像素直线」全部归因于 `hist[23:8] + Y_SHIFT=10` 的"两级右移叠加"。**这个归因是错的，已用 A/B 仿真证伪**：`(s >>> 8) >>> 10` 与 `s >>> 18` 在数学上**恒等**（算术右移可结合），所以 F4 的改动是「把隐式的两级移位合并成一级」的**行为等价重构**，它本身不改变任何一个像素。真正决定波形可见性的是 **F3**：只要输入是 16bit 符号扩展（±32767），无论 Y_SHIFT 是 10 还是 18，波形都只有 1..2 行；只有先左移到 24bit 满幅，两种实现才会一起变成 10~14 行。见 §3.2 的 A/B 实测表与 §2.3 的修订说明。

## 2. 逐条改动：前 / 后对照

### 2.1 F1 —— `rtl/audio/audio_src_mux.v:72-74`（8.3 短名字节序）

**改前**

```verilog
parameter [87:0] NAME_BGM   = {"BGM",  40'h20_20_20_20_20, "WAV"},
parameter [87:0] NAME_NARR  = {"NARR", 32'h20_20_20_20,    "WAV"},
parameter [87:0] NAME_ALARM = {"ALARM", 24'h20_20_20,      "WAV"}
```

**改后**

```verilog
parameter [87:0] NAME_BGM   = {8'h56, 8'h41, 8'h57, 40'h20_20_20_20_20, 8'h4D, 8'h47, 8'h42},             // "BGM     WAV"
parameter [87:0] NAME_NARR  = {8'h56, 8'h41, 8'h57, 32'h20_20_20_20,    8'h52, 8'h52, 8'h41, 8'h4E},       // "NARR    WAV"
parameter [87:0] NAME_ALARM = {8'h56, 8'h41, 8'h57, 24'h20_20_20,       8'h4D, 8'h52, 8'h41, 8'h4C, 8'h41}  // "ALARM   WAV"
```

**为什么反着写**：Verilog 拼接运算符把**最左操作数放最高位**，而 `rtl/storage/fat32_reader.v:683-693` 是：

```verilog
5'd0:  exp_byte = target_name[7:0];     // 目录项 offset 0（短名首字符）
5'd1:  exp_byte = target_name[15:8];    // offset 1
...
5'd10: exp_byte = target_name[87:80];   // offset 10（扩展名末字符）
```

即 `target_name[7:0]` 必须等于文件名的**第 0 个字符**。旧写法 `{"BGM", …, "WAV"}` 里 'B' 落在最高位、'V' 落在最低位 ⇒ `target_name[7:0] = 0x56('V')`，而磁盘上 `BGM.WAV` 的 offset 0 是 `0x42('B')` ⇒ `nm_bad` 恒真 ⇒ `name_hit` 永不成立 ⇒ `err_code=4/6` ⇒ `W_FAIL` ⇒ 永久沉默。

> 这三条常量与 `sim/testbench/tb_audio_src_mux.v:44-52` 中被参数覆盖的那三条**逐字节一致**（那三条在单元回归里已用过很久，是正确的写法）。三个名字的空格数各不同：BGM 3+5+3、NARR 4+4+3、ALARM 5+3+3，合计必须恰好 11 字节，多一个字节会被静默截掉高位。

**为什么单元 tb 一直全绿**：所有 tb 都用 `#(.NAME_BGM(...))` 覆盖了默认值，唯独顶层 `dmz_eg4s20_hdmi_top.v` 例化时没有覆盖 ⇒ 进综合的是 RTL 里的错误默认值。因此本次在 `tb_audio_src_mux.v` 里加了**故意不覆盖参数的第二个 DUT** 来守这条（见 §4.1 S13）。

### 2.2 F3 —— `rtl/audio/wav_stream_player.v:462-465`（位深左对齐）

**改前**

```verilog
sample_l <= {{8{fifo_q[15]}}, fifo_q};   // 16bit → 24bit 符号扩展
sample_r <= {{8{fifo_q[15]}}, fifo_q};   // 单声道复制到右声道
hold_l   <= {{8{fifo_q[15]}}, fifo_q};
hold_r   <= {{8{fifo_q[15]}}, fifo_q};
```

**改后**

```verilog
sample_l <= {{8{fifo_q[15]}}, fifo_q[15:0], 8'h00};   // 16bit 左对齐到 24bit
sample_r <= {{8{fifo_q[15]}}, fifo_q[15:0], 8'h00};   // 单声道复制到右声道
hold_l   <= {{8{fifo_q[15]}}, fifo_q[15:0], 8'h00};
hold_r   <= {{8{fifo_q[15]}}, fifo_q[15:0], 8'h00};
```

16bit 满幅只占 24bit 满幅的 1/256（`20*log10(256) = 48.16 dB`），符号扩展只是把数值搬进更宽的容器、数值大小不变。左移 8 位才是位深提升（LSB 补 0）。

**必须四处一起改**：`sample_l/sample_r` 直接进 `vol_apply` → HDMI / PWM / 波形；`hold_l/hold_r` 是 FIFO 空（欠载）时的保持值。两者口径不一致时，欠载前后会有 −48 dB 的音量跳变。
`:398-399` 与 `:729-730` 的 `hold_l/hold_r <= 24'sd0` 是复位/清空，**保持 0 是正确的**，未动。

### 2.3 F4 —— `rtl/video/audio_waveform.v`（波形幅度全链路，行为等价重构）

四处必须同时改，缺一处等于没改：

| 位置 | 改前 | 改后 |
|---|---|---|
| `:74` 参数 | `parameter integer Y_SHIFT = 10` | `parameter integer Y_SHIFT = 18` |
| `:97` 历史 | `reg signed [15:0] hist [0:HISTORY-1]` | `reg signed [23:0] hist [0:HISTORY-1]` |
| `:114` 入史 | `hist[0] <= audio_sample[23:8];` | `hist[0] <= audio_sample;` |
| `:128-129` 中间量 | `wire signed [15:0] s_curr/s_prev` | `wire signed [23:0] s_curr/s_prev` |
| `:140-141` 结果 | `wire signed [15:0] y_curr_s/y_prev_s` | `wire signed [23:0] y_curr_s/y_prev_s` |

`:142-143` 的 `y_curr = y_curr_s[9:0]` 保持不变。

**为什么 `Y_SHIFT` 是 18**：本模块的可见窗口是 `y ∈ [Y_CENTER-32, Y_CENTER+31] = [376, 439]`（64 行）。24bit 满幅 ±8 388 608：

- `>>> 18` → ±32 行 → `y ∈ [376, 439]`，**正好填满窗口**
- `>>> 17` → ±64 行 → `y ∈ [344, 471]`，下沿 471 压到滚动字幕带 `y=448..463`，而 `px_wave` 在 `video_overlay` 优先级链里**高于** `px_caption`，满幅时会把字幕糊掉

**为什么不能只改 `hist` 不改 `s_curr`**：`hist[idx]` 是 24bit，若 `s_curr` 仍是 16bit，赋给 `s_curr` 会**截掉低 16 位** —— 对左对齐的 16bit WAV 样本来说，低 16 位恰好全是 0，剩下的高 8 位只有符号，等于把波形又压回去。这是方案 4b 最容易漏的一处。

资源：`64×24bit = 1536` 个寄存器（旧 1024，+512），`rtl/video/audio_waveform.v:27-28` 记录 EG4S20 当前余量 REG 16k / LUT 12k 空闲，增量远小于余量。

#### ⚠ 修订（2026-11-03 22:02）：F4 是行为等价重构，不是可见性的充分条件

初稿写「两级右移共 18 位 → 波形恒为 1 像素直线」，暗示改 F4 就能让波形出现。**`tb_wave_ab.v` 的同输入 A/B 实测证伪了这个因果**：

```
[AB/raw  ] BEFORE (hist[23:8]+Y_SHIFT=10): widest=2 rows | last frame y 407..408 h=2 px=520
[AB/raw  ] AFTER  (hist[23:0]+Y_SHIFT=18): widest=2 rows | last frame y 407..408 h=2 px=520
[AB/shift] BEFORE (hist[23:8]+Y_SHIFT=10): widest=10 rows | last frame y 405..412 h=8 px=568
[AB/shift] AFTER  (hist[23:0]+Y_SHIFT=18): widest=10 rows | last frame y 405..412 h=8 px=568
```

- `raw` = 修复前 `wav_stream_player` 的真实输出（16bit 符号扩展，±32767）
- `shift` = 修复后 `wav_stream_player` 的输出（16bit << 8，±8388607）

**原因**：算术右移可结合，`(s >>> 8) >>> 10 ≡ s >>> 18`。旧实现的"两级移位"不是 bug，只是把 18 位拆成了 8+10 两步写。因此：

1. **波形不可见的根因是 R3（位深未左对齐），不是 R5**。修好 F3 后，**即使完全不动 `audio_waveform.v`，波形也会从 1..2 行变成 10~14 行**。
2. F4 的价值不在"让波形出现"，而在：(a) 24bit 全精度入史，不再预先丢低 8 位（将来若音源改成真 24bit，旧实现会白丢 8 位精度）；(b) 去掉 `hist` 与 `Y_SHIFT` 之间隐藏的耦合——旧实现的 `Y_SHIFT=10` 只在"上游已右移 8 位"的前提下才等价于 18，任何人单独改 `Y_SHIFT` 或单独改上游位深都会静默失效，这是本次踩坑的机制；(c) 参数语义变成"总位移 = Y_SHIFT"，可被 `tb_audio_waveform` ⑩ 段直接断言。
3. 因此 §3.2 的对照表必须按「F3 前 / F3 后」而非「F4 前 / F4 后」来读。表已重排。

### 2.4 F5 —— `rtl/top/dmz_eg4s20_hdmi_top.v:1124`（HDMI 侧衰减）

**改前** `localparam HDMI_AUDIO_ATTEN_SHIFT = 6;` **改后** `localparam HDMI_AUDIO_ATTEN_SHIFT = 2;`

三层衰减串联（改前）：

```
位深未对齐 −48.16 dB  +  vol_apply 档 6 −2.87 dB  +  ATTEN_SHIFT=6 −36.12 dB  =  −87.15 dB
```

改后：`0 + (−2.87) + (−12.04) = −14.91 dB`。

**为什么是 2 不是 0**：`ip/local/hdmi/enc/hdmi_1_4b_transmitter_core_wrapper.enc.v` 是 Anlogic 加密核，满幅钳位行为不可读，仓库与 `docs/` 里也没有 APUG092。改 0 是拿未知的削波风险换响度；取 2 留 4 倍（+12 dB）余量，配合 `vol_apply` 档 9（32/32 直通）峰值也只到核输入满幅的 25%。**若上板实测削波，降到 1 或 0；若仍偏小，说明问题不在这一层。**

**设计判断（要写进文档的结论）**：`HDMI_AUDIO_ATTEN_SHIFT` 的问题不是数值大小，而是它把音量权威拆成了两处、其中一处硬编码不可调。它只能是"接收端安全垫"，音量权威必须唯一地留在 `vol_apply` 的 10 档。改这个参数时要同步更新 `docs/hdmi_audio_2026-10-26.md`。

**错误码 → 数码管映射（逐条对应 `wav_stream_player.v:53-63` 的真实编码）**：

| `err_code` | 含义（源码 `wav_stream_player.v`） | 显示 | 用户读法 |
|---|---|---|---|
| 0 | 无错 | — | 正常 |
| 1 | RIFF/WAVE 标识不符 | `F1` | 文件不是 WAV / 拷贝被截断 |
| 2 | fmt chunk 缺失或 `audio_format ≠ 1` | `F2` | 非 PCM（MP3 改名 / 压缩 WAV） |
| 3 | `bits_per_sample ≠ 16` | `F3` | 位深不支持（8/24/32 bit） |
| 4 | `sample_rate ≠ 48000` | `F4` | 采样率不支持（44.1k / 22.05k） |
| 5 | 数据被截断 | `F5` | 文件不完整 |
| **6** | **文件未找到 / FAT32 定位失败** | **`C1`** | **卡上没这个文件（最常见）** |
| 7 | 读块失败（SD 层 `blk_err`） | `d7` | 卡接触不良 / 坏块 |
| 8 | 等 `blk_done` 握手超时 | `d8` | 卡响应超时 |
| 9 | 声道数 ≠ 1 | `F6` | 立体声 WAV（本设计只支持单声道） |
| 其它 | — | `d9` | 未归类 |

**为什么复用既有字母而不新增**：`seg_decoder` 与 `osd_font8x16` 只实现 `0-9/A/b/C/d/E/F` 共 41 个字形（`err_prompt.v:133-138` 注释「必须落在 seg_decoder 已实现的字符集内」）。新增字母要同时改两张表并重新生成字库，收益远小于成本。`C1` 与 SD 层 `sd_err=1` 的 `C1`（"卡上没这个文件"）读法一致，也与 t9 给 RLE 的 `d6`（卡上无 SCI.RLE）语义并列不冲突。

`wav_underrun` **刻意不接 `err_prompt`**（与 `rle_underrun` 同理）：欠载是性能抖动，不是故障；接进来会让播放中的正常抖动盖掉播放状态显示。

### 3.2 波形幅度（像素行数，实测）

**这张表必须按「F3 前 / F3 后」来读，不是「F4 前 / F4 后」**（原因见 §2.3 修订段：`(s>>>8)>>>10 ≡ s>>>18`，F4 行为等价）。

| 真实 BGM 中段 4096 样本 | **2 行**（最宽一帧）；末帧 2 行 | **14 行**（最宽一帧）；末帧 8 行 | `tb_wave_ab` 组 raw / 组 shift |
| NARR 峰值 29162 | 1 行（`y_off=0`） | **28 行**（`y_off=28`） | `tb_audio_waveform` ⑩-2 / ⑩-3 |
| 24bit 满幅三角波扫全量程 | — | **64 行**（y 376→439） | `tb_audio_waveform` ⑩-1 |
| tone_gen 三级串联（vol 6 / 应急 / vol 9） | 7 / 10 / 9 行 | **9 / 7 / 11 行**（同口径实测，见 §3.3） | `tb_chain_after` |

**A/B 同输入对照（`tb_wave_ab.v`，两个 DUT 吃同一串样本）**：

```
[AB/raw  ] BEFORE (hist[23:8]+Y_SHIFT=10): widest=2 rows  | last frame y 407..408 h=2 px=520
[AB/raw  ] AFTER  (hist[23:0]+Y_SHIFT=18): widest=2 rows  | last frame y 407..408 h=2 px=520
[AB/shift] BEFORE (hist[23:8]+Y_SHIFT=10): widest=10 rows | last frame y 405..412 h=8 px=568
[AB/shift] AFTER  (hist[23:0]+Y_SHIFT=18): widest=10 rows | last frame y 405..412 h=8 px=568
```

结论：
- **同一输入下，改前改后逐像素完全一致**（4 个数字对全等），证实 F4 是等价重构。
- 输入从 `raw` 换成 `shift`，波形从 2 行 → 10 行（末帧 2 → 8 行），**这才是可见性的来源**。
- 表中「真实 BGM 中段」一行用的是 `tb_wave_real_after` 的 4096 样本统计（最宽 14 行），与 `tb_wave_ab` 的 10 行口径略有差异：前者遍历全部 4096 个时刻取最大，后者按「每帧 64 点」统计后再取最大并含 63 样本预热边界，两者都远大于 1，不影响结论。

> 关于 tone 的场景：`audio_tone_gen` 的幅度固定 ±2 097 152，占 24bit 满幅的 25%，`>>>18` 后是 ±8 行 —— 这是设计上的正确结果，不是缺陷（tone 只是兜底提示音）。修复前后的 ±8 行数值巧合但成因不同：修复前是"上游只给了 16bit 量级 + 隐含两级右移"，修复后是"音源本身只有 25% 满幅"。若要它更明显，应调大 `audio_tone_gen` 的幅度（不在本次范围）。

### 3.3 三级串联实测（`tb_chain_after.v`，与 t2 的 `tb_audio_chain_diag` 同口径）

```
[S1 daily  ST_AUTO vol=6 ] frame scan: y_lo=405 y_hi=413 height=9  pixels=576
[S2 emerg  ST_EMERG vol=6] frame scan: y_lo=407 y_hi=413 height=7  pixels=608
```

## 5. R6：已知但本次不改

**现象**：即使 F1/F3/F5 全部修好，**只要卡有任何问题**（没插卡、格式不对、图库扫描失败、一次装载失败），用户仍然会"完全没声音"，而且连三角波兜底提示音都没有。

**机制链**（源码行号）：

1. `rtl/top/dmz_eg4s20_hdmi_top.v:859` `wire sd_or_gallery_fail = sd_fail || gallery_fail;`
2. `:960` `if (sd_or_gallery_fail || image_failed) playback_next = ST_FAIL;`（**最高优先级**，压过 `ST_EMERG`）
3. `rtl/audio/audio_tone_gen.v:142` `wire silent = mute || (playback_state == ST_IDLE) || (playback_state == ST_FAIL);`
4. `:152` `audio_valid <= sample_en;`（仍按 48 kHz 正常出） 但 `:154-155` `audio_left <= silent ? 24'sd0 : sample_out;`

`sd_fail` 与 `image_player.failed` 都是**粘滞电平**（`rtl/storage/sd_probe.v:93` `P_FAIL = 3'd5; // 终态: 任一环节失败，sd_fail 恒 1`、`:166`；`rtl/storage/image_player.v:362/386/388/394/434` 置 1，只有 `:253/:411` 清 0）⇒ 一次失败就永久沉默，直到整板复位。

**为什么本次不改**：

- R6 不是"音频缺陷"，是**状态机的设计取舍**：`ST_FAIL` 时系统本来就不该播放任何音频，否则用户会以为"能出声就是好的"，反而不去看数码管的错误码。真正的问题是"没有提示音"，而提示音已经有**独立通道**：`buzzer_tone`（顶层 `:1336`，引脚 H11）在 `alarm_req` 时响 A4 告警音。
- 改 `silent` 判据会改变三个模式的全局听觉语义，牵连 `tb_audio_chain_diag` 的 S1..S4 口径与 `tb_hdmi_audio_path`，属于需要单独评估的改动面，不该塞进本次修复。
- F1/F3 修好后，只要卡是对的正常播放；若卡有问题，用户会看到数码管错误码（下条），可自行定位。

**上板时的判别方法**（R6 触发时用户看到什么）：

| 观察点 | 正常 | R6 触发 |
|---|---|---|
| LED7（`err_active`，顶层 `:1373` `assign led = {err_active, …}`） | 灭 | **亮** |
| 数码管 DIG2/DIG3 | 显示播放状态 0..5 / 图号 | 显示**助记字母 + 数字**（`C1`/`F2`/`b1`/`d6`…） |
| 声音 | 有 BGM | **完全无**（HDMI 与 3.5mm 都没有） |
| 蜂鸣器 | 按键音 | 可能响 A4 告警音 |

> 注意：**DIG3 永远不会显示 "6"（ST_FAIL）**。因为 `:1383` `state_value = err_active ? prompt_hi : {1'b0, playback_state}` —— 只在 `err_active==0` 时才显示 `playback_state`，而 `ST_FAIL` 的三个触发条件（`sd_fail`/`gallery_fail`/`image_failed`）在 `err_prompt.v:201/231/273` **全部**映射为 `err_active=1`。判 ST_FAIL 要看"**LED7 亮 + DIG3 是字母**"，不是看数字 6。
