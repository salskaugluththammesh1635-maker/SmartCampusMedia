- 任务：t7（attempt `6b28539e-39e4-48ef-9386-816646d03c32`）

- 日期：2026-11-03

## 0. 一句话结论

现象①「像素偏移」与现象⑤「一堆黑边」是**同一个根因的两个面**：`image_window_mask` 在 t7-B 之后只按 Key9 档位窗口（`ratio_map` 的 `k9_win_*`）判决，**丢掉了「帧缓存这一块到底有没有被写过」这一维**；而 `img_scaler` 只写它自己的 letterbox 窗口、帧缓存其余区域保留上一帧/上电随机内容，整个设计**没有任何清屏逻辑**。于是窗口外的区域直接漏出残影，视觉上既像"位置不对"又像"一堆黑边"。

本次修复 = **把写入侧几何补回判决**（`in_window && in_image`），并修掉掩盖该缺陷的三处问题：日常模式 fade 分支漏提交 `display_*`、科普（ext）模式下 `display_*` 沿用了最后一张 BMP 的 letterbox 矩形、以及两个 TB 一直在验证**出货配置里不存在的接线**。

## 1. 四项改动的前后代码对照

### 改动 1：`rtl/video/image_window_mask.v` —— 判决改为两个矩形的交集

`rtl/video/image_window_mask.v`（43 → 72 行，LF，无 BOM）

**前**（端口只有 Key9 一路几何）：

```verilog
    input  wire [15:0]          win_w,
    input  wire [15:0]          win_h,
    input  wire [15:0]          win_off_x,
    input  wire [15:0]          win_off_y,
    input  wire                 pixel_valid,
    output wire                 pixel_valid_out
);
    ...
    wire in_window = (x_now >= win_off_x) && ({1'b0, x_now} < x_end) &&
                     (y_now >= win_off_y) && ({1'b0, y_now} < y_end);
    assign pixel_valid_out = de && pixel_valid && in_window;
```

**后**（新增写入侧矩形 `img_*`，`:47-50`、`:65-70`）：

```verilog
    input  wire [15:0]          win_off_y,
    // 写入侧几何：img_scaler 本次实际写入帧缓存的矩形（来自 image_player 的
    // out_*，即 display_*）。与上面 win_* 是**交集**关系，见文件头说明。
    input  wire [15:0]          img_w,
    input  wire [15:0]          img_h,
    input  wire [15:0]          img_off_x,
    input  wire [15:0]          img_off_y,
    input  wire                 pixel_valid,
    output wire                 pixel_valid_out
);
    ...
    // 写入侧矩形：同样的半开区间与加法上界。
    wire [16:0] img_x_end = {1'b0, img_off_x} + {1'b0, img_w};
    wire [16:0] img_y_end = {1'b0, img_off_y} + {1'b0, img_h};
    wire in_image = (x_now >= img_off_x) && ({1'b0, x_now} < img_x_end) &&
                    (y_now >= img_off_y) && ({1'b0, y_now} < img_y_end);
    // 交集：只有「Key9 允许显示」且「帧缓存这一块真被写过」的像素才放行。
    assign pixel_valid_out = de && pixel_valid && in_window && in_image;
```

设计取舍（三条，均写进文件头）：

1. **为什么是交集而不是替换**：只判 `win_*` 会漏出残影（现象⑤）；只判 `img_*` 会让 Key9 五档全部失效（回归 t7-B 裁定）。两个都要。
2. **上界一律用加法**（沿用原风格）：尺寸为 0 时减法会回绕成 `off-1`，把整片判成窗口内。
3. **`img_w = 0` 的语义**：`image_player` 复位后 `out_*` 全 0，表示"还没提交过任何帧" ⇒ `in_image` 恒假 ⇒ 全屏屏蔽（黑屏，而不是放行随机内容）。

### 改动 3：`rtl/storage/image_player.v` —— 三处翻帧点统一提交 `display_*`，并区分 ext / BMP 两种几何

`rtl/storage/image_player.v`（685 行，CRLF）

**(3a) 新增满帧常量**（`:122-123`，`FRAME_SPAN` 之后）：

```verilog
	localparam [15:0] FRAME_W16 = WIDTH;
	localparam [15:0] FRAME_H16 = HEIGHT;
```

> 用 `[15:0]` localparam 而不是 `WIDTH[15:0]`：`WIDTH` 是无位宽 `parameter`，部分工具不接受对 parameter 做部分选择。

**(3b) 新增选择器**（`:203-206`，`scale_*` 声明之后 —— 位置有讲究，Verilog 的 wire 引用要求先声明）：

```verilog
	wire [15:0] disp_w_sel = ext_wr_mode ? FRAME_W16 : scale_w;
	wire [15:0] disp_h_sel = ext_wr_mode ? FRAME_H16 : scale_h;
	wire [15:0] disp_x_sel = ext_wr_mode ? 16'd0     : scale_off_x;
	wire [15:0] disp_y_sel = ext_wr_mode ? 16'd0     : scale_off_y;
```

理由（写进 `:196-202` 注释）：ext（科普/RLE 视频）写口一帧写满 `WIDTH×HEIGHT@(0,0)`，与 BMP 的 letterbox 无关；但 `scale_*` 只由 `bmp_parser` 的 `hdr_ok` 驱动，科普模式下 `bmp_load_req = load_req && !ext_wr_mode` 把 BMP 通路冻结，`scale_*` 停在最后一张 BMP 的矩形上。不区分的话，换成 RES400（400×300@(120,90)）就会把视频裁成中间一块、四周 120/90 像素黑框。

**(3c) 三处翻帧点全部改为 `disp_*_sel`**（参考：`git show HEAD:rtl/storage/image_player.v` 为 `scale_*`/缺失）

| 位置 | 场景 | 前 | 后 |
|---|---|---|---|
| `:312-315` | 首帧提交（`!image_ready`） | `display_* <= scale_*` | `display_* <= disp_*_sel` |
| `:328-331` | 消隐期硬切换（`!FADE_ON \|\| ext_no_fade` 且 `vblank_rise`） | `display_* <= scale_*` | `display_* <= disp_*_sel` |
| `:354-357` | fade 分支（`fade_alpha==0 && vblank_rise`） | **完全缺失** | `display_* <= disp_*_sel` |
| `:276-279` | 复位 | `16'd0` | `16'd0`（不变） |

第三行是本次修的独立缺陷：日常模式（`FADE_ON = FADE_EN && (FADE_FRAMES>1) = 1`，且 `ext_no_fade = rle_play_en = 0`）**只走 fade 这条路径**，`display_*` 会永远停在首帧的值上。6 张素材全 640×480 时首帧就是 640/480/0/0，与之后任何一帧相同，缺陷被素材完全掩盖 —— 一旦卡上换成 RES400/512/576，表现就是"**只错日常模式、切到科普就正常**"这类最难查的偏态故障。

## 2. TB 断言条数变化（每条在保护什么）

| 文件 | 断言计数 | HEAD | 现在 | 增量 |
|---|---|---|---|---|
| `sim/testbench/tb_image_player.v` | `chk(` | 59 | **91** | +32（含 t9 的 CASE15 贡献 9 条） |
| `sim/testbench/tb_image_window_mask.v` | `expect_valid(` | 20 | **52** | +32 |

`tb_image_player` 本次新增的保护：

- **`disp_geom` 采样块**（`always @(posedge clk)`，条件 `rst_n && SEAMLESS && (dut.front_sel !== front_sel_d) && image_ready_d`）：每次翻帧比对 `dut.display_*` 与期望几何，累计 `disp_geom_ok` / `disp_geom_bad`。期望值由 **TB 独立计算**，不复用 DUT 的选择器：

  ```verilog
  wire [15:0] exp_disp_w = ext_wr_mode_r ? W[15:0] : dut.scale_w;
  wire [15:0] exp_disp_h = ext_wr_mode_r ? H[15:0] : dut.scale_h;
  wire [15:0] exp_disp_x = ext_wr_mode_r ? 16'd0   : dut.scale_off_x;
  wire [15:0] exp_disp_y = ext_wr_mode_r ? 16'd0   : dut.scale_off_y;
  ```

- **CASE 2 内 2 条**：`disp_geom_bad == 0`（翻帧后几何必须跟着新帧走）、`disp_geom_ok >= 1`（该路径真的跑过，防止断言因"从未采样"而恒真）。
- **CASE 16（新增，日常 fade 路径 + 半幅源图）10 条**：先装 W/2×H/2 的 BMP，让 `display_*` 与 `scale_*` **可能分离** —— 这是整个 tb 第一个来源尺寸 ≠ 容器尺寸的用例（其余用例的源图尺寸都等于容器尺寸，与上板"6 张素材全 640×480"是同构掩盖）。断言 `display_w/h/off_x/off_y` 分别等于 `W/2`、`H/2`、`W/4`、`H/4`，并复查 `disp_geom_bad/ok`。
- **CASE 17（新增，ext 模式强制满帧）10 条**：先把 `scale_*` 打成 320×240@(160,120)，再切 `ext_wr_mode`、注入 `ext_wr_done` 翻帧，断言 `out_w/out_h` = 640/480、`out_off_*` = 0，且 `disp_geom_bad == 0`。这是钉住 `disp_*_sel` 契约的唯一用例。

`tb_image_window_mask` 新增 32 条（第 ⑥ 组）：

- **6.1**（8 条）Key9 满屏 + 源图 320×240@(160,120) ⇒ 只有 img 块放行，四周补黑。
- **6.2**（4 条）Key9 非满屏 320×240@(160,120) + 图像全幅 ⇒ 交集 = Key9 窗口（**证明没有回退 t7-B**）。
- **6.3**（6 条）部分重叠（win `[160,480)×[120,360)` vs img `[200,520)×[150,390)`）⇒ 严格等于重叠矩形。
- **6.4**（3 条）完全不相交 ⇒ 一个像素都不放行。
- **6.5**（2 条）`img_w = 0`（还没提交过帧）⇒ 全屏蔽。
- **6.6**（9 条）ext 写口满帧 + 满屏窗口 ⇒ 四角全放行；ext + Key9 320×240 ⇒ 只 Key9 窗口内放行；**反例守卫**：img 错留成 400×300@(120,90) ⇒ `(0,0)`、`(119,240)` 必须屏蔽而 `(120,90)` 必须放行。

## 5. 「必须上板才能确认」与「改素材即可解决」的分界

### 5.1 改素材即可解决、不需要任何 RTL 改动

- **黑边的绝对面积**。若卡上放的是 `assets/v2/sdcard/BURN640`（6 张全 640×480），`img_scaler` 走 1:1 且 `sq_w8 = 640`、`sq_off = 0`、`out_off_y = 0`，**铺满整屏、零黑边**。用户看到的"一堆黑边"对应的是 RES512 及以下档位（RES512 = 36.00%、RES400 = 60.94%、RES320 = 75.00% 面积被屏蔽）。
- **"自适应缩放"这件事本身**：本设计**只缩不放**（`img_scaler.v:159` 的 `shrink` 判据 + `ARCHITECTURE.md:135` 的架构论证）。小于 640×480 的源图按 1:1 居中，这是设计意图，不是 bug。想让中等尺寸图真正铺满，唯一低成本路径是**在 `scripts/gen_assets_v2_sdcard.py` 侧把素材重采样到 640×480**（母版 1920×1440 → LANCZOS 一步到位），零 RTL 改动、零综合、零时序风险。
- **`bmp_parser` 的 `CHECK_SIZE` 不是可改项**：`image_player.v:436` 已经是 `.CHECK_SIZE(0)`，任意分辨率都能通过校验。

### 5.2 必须上板才能确认

1. **黑边区域到底是"纯黑"还是"残影"**。改完之后两者都应该是纯黑（`in_image` 恒假 ⇒ `video_content_mux` 输出 `24'd0`）。仿真里只能证明 `pixel_valid_out` 为 0，**无法证明面板实际显示黑色**（下游还有 `fade_mixer`、`brightness_apply`、`osd_panel`、HDMI 核）。
2. **日常 / 科普两种模式下窗口几何是否真的一致**。仿真里 `ext_no_fade` / `FADE_ON` 两个分支都覆盖到了，但两者在上板的切换时序（`rle_play_en` 何时翻转）无法在仿真复现。
3. **RLE 视频（科普模式）本身是否工作**。本次只保证 ext 模式写入帧缓存的那一帧被判定为满帧；`rle_decoder` 是否真的在出像素是 t9 的范围，与本次修复无关。
4. **面板左边框是否 1 像素错位**。`brightness_apply` 是纯组合（无寄存器），若有人在链路上加了拍点，`active_x/active_y` 与像素会错 1 拍 —— 这类问题**仿真波形抓不到**，只有上板盯着面板左边框才看得出。
